#### Summary
MoE inference on consumer hardware is bottlenecked by weight memory—a 35B-class model occupies 19.5 GB at 4-bit, and sparsity reduces compute per token without reducing bytes stored. Naive SSD offloading fails because expert selection for layer N+1 requires layer N's output, preventing early prefetching. Edge0 introduces a prerouter: a lightweight per-layer head predicts the next layer's expert routing one token ahead, enabling SSD reads to overlap with compute with no expert dropping. A recovery LoRA trained on the student path compensates quality loss from INT4 quantization and routing replacement. On a single 24 GB machine, Edge0 serves a 35B MoE at 20 tok/s within 3 GiB of peak active memory, matching its fp16 teacher within a few points across five public benchmarks.

- 🎯 Prerouter predicts next-layer expert routing one token ahead, fully hiding SSD prefetch latency behind compute with no expert drops
- 🎯 Unmerged recovery LoRA trained on the student path compensates for INT4 quantization and routing-replacement quality loss
- 📊 Serves a 35B MoE at 20 tok/s on a single 24 GB machine with only 3 GiB peak active memory, near fp16 teacher quality on five benchmarks
- 🔧 Framework, checkpoints, and adapters are open source; same framework supports an 8B tier

#### Summary
W4A4 quantization typically requires expensive cross-layer propagation of basis transforms, creating architecture dependencies and high calibration costs. MACaQ applies a per-channel scale and block-Hadamard transform independently to each linear layer's activations, absorbing the inverse transforms into the weights for a streaming, single-layer-in-memory calibration pipeline. A Hessian-aware Flip-Refinement coordinate-descent procedure further improves MXFP4 code assignment. MACaQ adds only 2.3% end-to-end overhead on Qwen3-32B in vLLM, quantizes Llama-3-8B 11× faster than DuQuant++ and MR-GPTQ while matching their perplexity, and handles a 122B-parameter model in 64 minutes using 32.5GB GPU RAM.

- 🔧 122B-parameter model quantized in 64 minutes using only 32.5GB GPU RAM; generalizes to image diffusion models without architecture-specific changes

#### 🧭 Why this paper
**Pruning / distillation** · topic 4/5 · practicality 3/5 · composite 7/10 · Concertina proposes folding N adjacent teacher layers into a shared block executed N times, each carrying a low-rank correction and per-token gate. The method is a combination of structural compression and knowledge distillation, with open-sourced code and a clean design. The largest experiment uses Qwen3-4B (compressed to 2.27B) validated on 8 benchmarks including commonsense and mathematical reasoning, surpassing same-size baselines and Qwen3-1.7B. #### Summary
Standard knowledge distillation trains a compact student from scratch, requiring large amounts of data despite the teacher's weights already encoding the necessary knowledge. Concertina folds every group of N adjacent teacher layers into one shared block executed N times; each loop step carries a low-rank correction initialized from the layer it replaces, and a per-token gate mixes these corrections to recover the original layer behaviors from a single block. A distillation data recipe balancing general, mathematical, academic, and multiple-choice data is designed to recover all teacher capabilities simultaneously. Applied to Qwen3-4B, a 2.27B Concertina model distilled on 22B tokens retains ~90% of teacher performance on commonsense and mathematical reasoning and 84% on average across eight benchmarks, outperforming same-size dense and layer-sharing baselines as well as Qwen3-1.7B trained on over 1,000× more data.

- 📊 Outperforms same-size dense and layer-sharing baselines and Qwen3-1.7B trained on >1,000× more data
- 💡 Distillation data recipe balances general, math, academic, and multiple-choice data to avoid capability trade-offs

- Qwen3-1.7B — trained on >1,000× more data yet outperformed by 2.27B Concertina
