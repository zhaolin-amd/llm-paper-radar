#### 🧭 为什么推送这篇
**KV cache 压缩** · topic 4/5 · practicality 4/5 · composite 8/10 · OasisKV是一个基于vLLM的KV cache卸载与稀疏预取系统，利用speculative decoding生成的lookahead tokens预测下一步所需KV块，并从host/远端内存提前搬到HBM，本质上是KV cache eviction与多级存储分层的结合。系统已在vLLM上实现，具备实际部署基础，吞吐提升1.69-2.1x，精度损失极小（0.1-0.7点）。但论文未明确报告MMLU/GSM8K/HumanEval等标准下游基准（abstract仅提到accuracy points相对full attention），且speculative decoding只作为lookahead预测工具而非主要压缩贡献。整体属于KV cache compression范畴，系统设计清晰、有vLLM实现、无需离线校准，practicality较高，但缺乏标准benchmark评测使topic_relevance略降至4。

#### 🌊 Paper River
[倒读批判链](../paper-river/OasisKV-2608.08097.org)

#### 摘要
LLM 推理在长上下文和长链推理负载下，KV cache 对 HBM 容量形成严重压力。OasisKV 将 KV cache 的完整存储从 HBM 卸载至 host/远端内存，利用 speculative decoding 生成的 lookahead tokens 提前预测下一步所需的重要 KV block，并通过后台 attention pipeline 在下一 decode 步骤前将其预取到 HBM。在 2048-token KV budget 下，精度与 full attention 相差不超过 0.7 点，吞吐在推理负载下提升 1.69×，长上下文多卡场景下提升至 2.1×；在 prefill-decode 分离部署下达到约 2× 的 dense 吞吐，同时将 KV 传输量降低 6.5–9.7×。

- 🎯 利用 speculative decoding 的 lookahead tokens 预测重要 KV block，通过后台 pipeline 从 host/远端内存预取至 HBM，实现 decode 时稀疏 attention
- 📊 2048-token KV budget 下精度与 full attention 相差 ≤0.7 点；推理负载吞吐 1.69×，多卡长上下文 2.1×（dense vLLM 基准）
- 📊 prefill-decode 分离部署下吞吐约 2×，KV 传输量降低 6.5–9.7×，decode 节点 host 内存占用降低 2.2–2.6×
- 🔧 基于 vLLM 实现，无需离线校准，运行时动态预测，具备实际生产部署基础

#### 📎 相关方法 / 对比基线

- speculative decoding — 作为 lookahead token 生成工具，用于预测重要 KV block 而非主要压缩手段
