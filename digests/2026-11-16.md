👥 Saksham Gupta (Carnegie Mellon University), Michael Li (Carnegie Mellon University) · 🏷 cs.LG, cs.AI
🔗 [arXiv](https://arxiv.org/abs/2611.20565) · [alphaxiv](https://www.alphaxiv.org/abs/2611.20565)
📡 Sources: arxiv
🧪 kv_cache · K4V4 per-channel keys / per-token values, KV cache quantization for draft model · cal: 数据无需重训练，PTQ量化，calibration成本低 · perf: draft cache内存减少66.20%，两cache合计减少23.95%

#### 🧭 为什么推送这篇
**KV cache 压缩** · topic 4/5 · practicality 4/5 · composite 8/10 · 本文将speculative decoding中的draft model KV cache进行INT4量化（K4V4），target model保持BF16不变，从而在不影响target correction rule的前提下显著减少内存。方法遵循KIVI风格（per-channel key / per-token value），算法简洁且calibration成本极低。核心贡献包括：(1) 系统研究key vs value精度分配的最优策略，发现quantizer layout对sensitivity分析结论有决定性影响；(2) 在六对模型上验证66%的draft cache节省，acceptance几乎无损。spec decoding + KV quant属于kv_cache bucket（以KV量化为主要压缩贡献）。评估指标主要是acceptance rate而非MMLU/GSM8K等标准benchmark，限制了topic_relevance上限；但方法简单、工程可落地性强，practicality给4分。

#### 摘要
Speculative decoding 需要同时维护 target 和 draft 两个 KV cache，造成额外显存开销。本文对 draft model 的 KV cache 进行 K4V4 量化（per-channel keys / per-token values），target cache 和 verifier 保持 BF16，确保 target correction rule 不受影响。研究发现 key vs. value 的精度分配结论强烈依赖于 quantizer layout：naive per-token key 量化使 K8V4 比 K4V8 高 10.87pp acceptance，而改用 per-channel key 后差距缩至 -0.25pp。在六对模型上，该方法将 draft cache 内存压缩 66.20%、两 cache 合计减少 23.95%，mean acceptance 仅从 57.93% 降至 57.14%（相对下降 1.36%）。

- 🎯 对 draft model KV cache 执行 K4V4 量化（per-channel keys / per-token values），target model 保持 BF16 不变
- 📊 draft cache 内存减少 66.20%，两 cache 合计减少 23.95%，acceptance 相对仅下降 1.36%（57.93%→57.14%）
- 💡 key/value 精度分配的灵敏度结论由 quantizer layout 决定：per-token key 下 K8V4 领先 K4V8 10.87pp，per-channel key 下差距缩至 -0.25pp
- 🔧 遵循 KIVI 风格，PTQ 无需重训练，工程落地成本低

#### 📎 相关方法 / 对比基线
- [KIVI](https://arxiv.org/abs/2402.02750) — 直接遵循其 per-channel key / per-token value 量化布局

- 🎯 理论刻画latent KV表示可直接执行RoPE的充要条件：映射需满足intertwining关系，精确混合限于相同RoPE频率坐标

#### 🧭 为什么推送这篇
**KV cache 压缩** · topic 4/5 · practicality 3/5 · composite 7/10 · MiSTiQ是一个面向KV cache的极低比特（~1.25 bits）压缩方法，将trellis coded量化与MX格式（如NVFP4）结合，在Llama3和Qwen3上验证了WikiText PPL、GSM8K和LongBench指标，对比codebook-based baselines有优势。方法创新点在于MX-Hash函数可直接在目标MX格式下生成重建值，避免高精度中间步骤，具备一定硬件加速潜力。但评估基准较窄（主要是PPL + GSM8K + LongBench，缺乏MMLU/HellaSwag等标准多任务benchmark），且beam search编码KV cache的运行时代价不明，实际部署路径尚需工程验证。topic_relevance降至4因benchmark覆盖有限；practicality定为3因trellis beam search编码复杂度较高，MX格式虽已有硬件支持但集成非trivial。

#### 摘要
LLM推理中KV cache随序列长度和批大小增长带来显存与内存带宽压力，现有codebook-based向量量化方法受硬件限制codebook规模，且需将缓存重建为高精度浮点格式才能参与attention计算，削弱了量化的计算收益。MiSTiQ将trellis编码存储与microscaling（MX）格式结合：用带beam search的trellis量化在大重建空间上编码KV cache，同时推导MX-Hash函数直接在目标MX元素格式（如NVFP4）下生成重建值，避免高精度中间步骤。在Llama3和Qwen3上，约1.25 bits/element下，MiSTiQ在WikiText PPL、GSM8K accuracy和LongBench平均分上均优于所有对比的codebook-based baseline。

- 🎯 trellis量化+beam search在大重建空间编码KV cache，无需大codebook；MX-Hash函数直接生成MX格式重建值
- 📊 约1.25 effective bits/element下，Llama3和Qwen3上WikiText PPL和GSM8K accuracy均优于所有baseline
- 📊 使用NVFP4时，两模型上LongBench平均分均达最高
- ⚠️ beam search编码的运行时开销未量化，缺乏端到端speedup数据，benchmark覆盖有限
