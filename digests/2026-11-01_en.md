#### Summary
MoE inference on consumer hardware is bottlenecked by weight memory, not compute: a 35B-class model requires 19.5GB at 4-bit, and naive SSD offloading cannot hide read latency because expert selection for layer N+1 depends on layer N's output. Edge0 solves this with a prerouter—a per-layer head that predicts the next layer's routing one token ahead—so SSD prefetch fully overlaps with computation and no experts are dropped. An unmerged recovery LoRA, trained on the student routing path, compensates for quality lost to INT4 quantization and routing replacement. On a single 24GB machine, Edge0 serves a 35B MoE at 20tok/s within 3GiB of peak active memory, staying within a few points of the fp16 teacher across five public benchmarks.

- 🎯 Prerouter predicts next-layer expert routing one token ahead, fully hiding SSD read latency behind compute
- 📊 35B MoE served at 20tok/s on a single 24GB machine with only 3GiB peak active memory
- 💡 Unmerged recovery LoRA trained on the student path jointly recovers INT4 quantization and routing-replacement quality loss
- 🔧 Framework, checkpoints, and adapters are open-source; an 8B tier runs on the same framework

#### Summary
Edge inference for ternary LLMs such as BitNet b1.58 has lacked efficient system support. Bitnet.cpp targets the dominant bottleneck—mixed-precision matrix multiplication (mpGEMM)—with a dedicated library featuring two solutions: Ternary Lookup Table (TL), which eliminates the spatial inefficiency of prior bit-wise methods, and Int2 with a Scale (I2_S), which guarantees lossless inference. The system achieves up to 6.25x speedup over full-precision baselines and up to 2.32x over low-bit baselines, and is publicly available for CPU/edge deployment. An extension to element-wise lookup table (ELUT) for general low-bit LLMs is also presented.

- 🎯 Proposes TL (Ternary Lookup Table) and I2_S (Int2 with a Scale) for sub-2-bits-per-weight mpGEMM in ternary LLMs
- 📊 Up to 6.25x speedup over full-precision baselines and up to 2.32x over low-bit baselines
- 💡 TL resolves spatial inefficiency of bit-wise methods; I2_S ensures lossless edge inference
- 🔧 Data-free, no calibration required; targets commodity CPUs and edge devices; open-sourced
