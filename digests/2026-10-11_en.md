#### Summary
MoE inference on consumer hardware is bottlenecked by weight memory: a 35B model occupies 19.5GB at 4-bit, and sparsity reduces compute per token without reducing bytes to fetch. Naive SSD offloading fails because expert selection for layer N+1 depends on layer N's output, making early prefetch impossible. Edge0 addresses this with a prerouter—a per-layer lightweight head that predicts the next layer's expert routing one token ahead, using that prediction directly as the routing decision to fully pipeline I/O with compute. A recovery LoRA trained on the student path compensates for both INT4 quantization loss and routing replacement error. On a single 24GB machine, Edge0 serves a 35B MoE at 20tok/s within 3GiB peak active memory, staying within a few points of the fp16 teacher across five public benchmarks.

- 🎯 Prerouter predicts next-layer expert routing one token ahead; prediction serves directly as routing to fully pipeline SSD reads with compute
- 💡 Unmerged recovery LoRA trained on the student path compensates jointly for INT4 quantization error and routing replacement
- 📊 35B MoE at 20tok/s on a single 24GB machine with only 3GiB peak active memory; within a few points of fp16 teacher on five benchmarks
- 🔧 Framework, checkpoints, and adapters are fully open-sourced; 8B tier also supported on the same engine

#### Summary
Efficient edge inference for ternary LLMs such as BitNet b1.58 has remained largely unsupported. Bitnet.cpp addresses this with a dedicated mpGEMM library featuring two core techniques: Ternary Lookup Table (TL), which resolves spatial inefficiencies of prior bit-wise methods, and Int2 with a Scale (I2_S), which guarantees lossless inference. The system achieves up to 6.25x speedup over full-precision baselines and up to 2.32x over low-bit baselines on CPU edge devices. TL is further generalized to an element-wise lookup table (ELUT) for broader low-bit LLM applicability, with both theoretical and empirical support.

#### Summary
LLM deployment is bottlenecked by memory and compute demands, and existing quantization methods struggle to preserve fidelity below 1 bit per weight. LittleBit addresses this via low-rank latent matrix factorization followed by binarization of the resulting factors, achieving quantization rates as low as 0.1 BPW — compressing Llama2-13B to under 0.9 GB (~31× memory reduction). A multi-scale compensation mechanism learns importance parameters across row, column, and latent dimensions to counteract information loss, while Dual-SVID enables QAT initialization and Residual Compensation minimizes approximation errors. At 0.1 BPW on Llama2-7B, LittleBit surpasses competing methods operating at 0.7 BPW, and projects an 11.6× inference speedup over FP16.

- 📊 Llama2-13B compressed to under 0.9 GB (~31× memory reduction); theoretical 11.6× inference speedup vs FP16
- 📊 At 0.1 BPW on Llama2-7B, outperforms leading methods operating at 0.7 BPW
- ⚠️ Requires full QAT training (Dual-SVID + Residual Compensation); 11.6× speedup is theoretical with no measured kernel results
