#### Summary
Running 35B-class MoE models on consumer hardware faces a memory wall: at 4-bit quantization the weights occupy 19.5GB, and naive SSD offloading cannot hide I/O latency because layer N+1's expert selection depends on layer N's output. Edge0 introduces a prerouter—a per-layer head that predicts the next layer's routing one token ahead and whose prediction is used directly as the routing decision—enabling SSD reads to begin before the current layer finishes. A recovery LoRA trained on the student path (INT4 + prerouter routing) compensates for both quantization and routing-replacement quality loss. On a single 24GB machine, Edge0 serves a 35B MoE at 20 tok/s within 3 GiB of peak active memory, staying within a few points of the fp16 teacher across five public benchmarks.

- 🎯 Prerouter predicts next-layer expert routing one token ahead, using the prediction as the actual routing to enable early SSD reads
- 📊 Achieves 20 tok/s for a 35B MoE on a single 24GB GPU with only 3 GiB peak active memory
- 💡 Recovery LoRA trained on the full student path simultaneously recovers quality lost to INT4 quantization and routing replacement
- 🔧 Framework, checkpoints, and adapters are fully open-source; an 8B-tier MoE runs on the same system
