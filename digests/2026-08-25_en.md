#### Summary
Long-context prefill in LLMs suffers from quadratic attention cost; existing approaches either apply uniform low precision or perform token-level sparsity, leaving spatial precision routing inside fused dense attention unexplored. TileMix partitions the attention score matrix into hardware-aligned tiles, encodes routing decisions as compact bitmasks, and dispatches each tile group through either FP16 or INT8 score computation while maintaining a shared online-softmax state within a single fused kernel. Scalable precision grouping allows one routing bit to cover multiple adjacent key tiles, keeping metadata compact at long contexts. Without any training, TileMix preserves dense token connectivity, supports GQA, variable-length batches, and INT8 KV caches, recovering long-context quality lost under uniform INT8 and improving prefill throughput over FP16 on LongEval, LV-Eval, and A100 benchmarks across LLaMA, Qwen, and Vicuna.

- 🎯 Tile-centric FP16/INT8 spatial routing inside fused dense attention using compact bitmask-packed decisions and shared online-softmax
- 💡 Scalable precision grouping: one routing bit governs multiple adjacent key tiles, preserving hardware alignment and compact metadata at long contexts
- 📊 A100 prefill throughput exceeds FP16 while recovering long-context quality degraded by uniform INT8 (LongEval, LV-Eval)
- 🔧 Training-free, data-free; supports GQA, variable-length batches, INT8 KV cache; open-source CUDA kernel

#### Summary
While post-training quantization (PTQ) effects are well-documented on English benchmarks, their impact on morphologically complex, low-resource languages like Bangla remains unexplored. This study evaluates Qwen-2.5-7B, LLaMA-3.1-8B, and GPT-OSS-20B under three quantization formats (GPTQ-Int8, GPTQ-Q8, GGUF-W8A16) across five Bangla NLU benchmarks using zero-shot lm-evaluation-harness, constituting the first controlled comparison of quantization formats on Bangla NLU. The results show that architecture and quantization method choice matters more than bit width alone for low-resource language deployment.
