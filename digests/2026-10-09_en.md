#### Summary
35B-class MoE inference on consumer hardware is bottlenecked by weight memory—19.5GB at 4-bit—and naive SSD offloading fails because layer N+1's expert routing cannot be determined until layer N's output is ready, preventing early prefetch. Edge0 introduces a prerouter: a per-layer head predicts the next layer's routing one token ahead, and this prediction is used directly as the routing decision, enabling pipelined SSD prefetch that fully overlaps with compute. An INT4 quantization scheme and a recovery LoRA trained on the student path (INT4 + routing replacement) jointly recover accuracy loss. On a single 24GB GPU, Edge0 serves a 35B MoE at 20 tok/s within 3GiB of peak active memory, staying within a few points of its fp16 teacher across five public benchmarks.

- 🎯 Prerouter predicts next-layer expert routing one token ahead, eliminating SSD-prefetch stalls; staged and routed expert sets are identical
- 📊 Serves 35B MoE at 20 tok/s on a single 24GB GPU with only 3GiB peak active memory, within a few points of fp16 teacher on five benchmarks
- 💡 Recovery LoRA trained on the student path simultaneously compensates for INT4 quantization error and routing-replacement degradation
- 🔧 Full framework, checkpoints, and adapters are open-sourced; supports both 35B and 8B MoE tiers

#### Summary
LLM deployment is constrained by memory and compute requirements, and existing quantization methods struggle to preserve model fidelity below 1 bit per weight. LittleBit addresses this by representing weights via low-rank latent matrix factorization followed by binarization of the resulting factors, augmented with a multi-scale compensation mechanism across row, column, and latent dimensions. #### 🧭 Why this paper
**Pruning / distillation** · topic 5/5 · practicality 4/5 · composite 9/10 · SparseDecoding targets the memory bottleneck of the LLM decoding stage with two core contributions: (1) algorithmically, it replaces pre-collected natural sequences with dense-model autoregressive generation activations (prefill excluded) for Hessian calibration, eliminating distribution shift; (2) at the system level, it develops an optimized N:M sparse kernel with bitmask indexing and fixed-step traversal for SpMV operations, addressing the existing gap in SpMV support relative to SpMM. Validated on Llama-3.1-8B, Llama-3.3-70B, and Qwen3-14B/32B, achieving up to 1.48× end-to-end speedup on A100. The algorithmic approach is a targeted modification to existing Hessian pruning frameworks; calibration requires only a single forward autoregressive generation pass with the dense model—no gradient updates—making deployment overhead low. Main uncertainty: specific numbers for long-form generation benchmarks are not provided, and the N:M SpMV kernel requires a custom implementation, though N:M sparsity is a mature format with good A100 support, making engineering adoption feasible.

#### Summary
The memory-bound decoding stage of LLM inference suffers from high latency, and Hessian-guided training-free pruning methods face two key issues: (1) a distribution shift between pre-collected natural sequences used for Hessian computation and the self-generated tokens seen during actual decoding; (2) limited support for sparse matrix-vector (SpMV) operations that dominate decoding, as most methods target SpMM. SparseDecoding addresses both by constructing calibration matrices from layer-wise activations collected during dense-model autoregressive generation (excluding prefill), aligning the pruning objective with decoding-time activations, and by developing an optimized N:M sparse matrix-vector kernel with bitmask indexing and fixed-step traversal. Experiments on Llama-3.1-8B, Llama-3.3-70B, and Qwen3-14B/32B consistently outperform fixed-text calibration baselines on long-form generation benchmarks, achieving up to 1.48× end-to-end wall-clock decoding speedup on A100 GPUs.

- 🎯 Calibration matrices built from dense-model autoregressive generation activations (prefill excluded), eliminating Hessian distribution shift
- 🔧 Optimized N:M SpMV kernel with bitmask indexing and fixed-step traversal to accelerate decoding-dominant operations
- 📊 Up to 1.48× end-to-end wall-clock decoding speedup on A100 GPUs
- 📊 Consistently outperforms standard fixed-text calibration on long-form generation benchmarks across Llama-3.1-8B, Llama-3.3-70B, Qwen3-14B/32B
