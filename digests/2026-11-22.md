#### 摘要
Top-k sparse attention 的 indexer 通常需要在完整服务长度下进行蒸馏，训练代价高昂。本文发现短序列训练的 indexer 无法泛化到长上下文的原因主要在于 RoPE 位置编码，而非内容匹配能力下降，并据此提出 position-skipped distillation：在短序列训练时随机插入位置 ID 间隔，使 teacher 和 indexer 均只处理短序列。在 DeepSeek-V2-Lite 和 Qwen3-30B-A3B 上，8K 蒸馏的 indexer 在 32K 长度下与 32K 蒸馏版本 perplexity 差距约 0.5，在 64K 长度下与 64K 蒸馏版本相当，训练计算量约降低 6x。此外，indexer keys 量化到 3-4 bit 无需重训练，配合 fused integer kernel 使扫描速度比 half precision 提升 1.6-2.2x。

- 🎯 position-skipped distillation：随机插入位置 ID 间隔，仅用 8K 短序列训练 indexer 以覆盖长上下文
- 📊 DeepSeek-V2-Lite 上 8K 蒸馏在 64K 匹配 64K 蒸馏版本，训练计算量降低约 6x
- 🔧 indexer keys 量化至 4-bit 无需重训练，PPL 变化 ≤0.05，fused integer kernel 扫描速度 1.6-2.2x vs half precision
- ⚠️ 在 Llama-3.1-8B 上落后 32K 蒸馏 0.6 PPL，收益主要体现在训练成本而非质量

#### 摘要
量化通常通过perplexity和task accuracy评估，但这些指标无法捕捉一类特殊退化：某些token在量化后无法成为greedy decoder的输出（称为'silenced token'）。本文提出三种检测手段——可赢方向（certified safe）、距离上界（upper bound）、精确匹配（exact lower bound）——组合形成对silenced token数量的认证区间估计，在3 bit及以上几乎完全收紧为精确计数。在三个开源模型上发现：大词表模型在8-bit即出现silencing，1B参数模型可损失数百可达token；multilingual词表中非拉丁字符（韩语、中文、泰语、阿拉伯语、希伯来语）被silenced的比例远高于拉丁字符，尽管拉丁token在词表中占主导。

- 🎯 提出三种检测手段（可赢方向 / 距离上界 / 精确匹配）组合形成silenced token的认证区间，≥3 bit时两端基本重合，计数精确
- 📊 大词表模型在8-bit精度即出现silencing，1B参数模型可损失数百可达token，随精度下降而增长
- 📊 multilingual词表中被silenced的token绝大多数为非拉丁字符（韩语、中文、泰语、阿拉伯语、希伯来语），呈现显著语言不均匀性
- ⚠️ 仅提供诊断工具，不提出新量化算法；最大测试模型仅1B参数，无标准下游基准
