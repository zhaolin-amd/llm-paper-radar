#### Summary
MoE inference on consumer hardware is bottleneck by weight memory rather than compute: a 35B model occupies 19.5GB at 4-bit, and sparsity only reduces per-token FLOPs, not bytes loaded. Naive SSD offloading fails because expert selection for layer N+1 depends on layer N's output, preventing early reads from hiding behind compute. #### Summary
Ternary LLMs such as BitNet b1.58 face a practical bottleneck at edge deployment: mixed-precision matrix multiplication (mpGEMM) dominates inference time. Bitnet.cpp addresses this with a dedicated mpGEMM library featuring two core kernels: Ternary Lookup Table (TL), which fixes spatial inefficiencies of prior bit-wise methods, and Int2 with a Scale (I2_S), which guarantees lossless inference. The system achieves up to 6.25x speedup over full-precision baselines and up to 2.32x over low-bit baselines, enabling sub-2-bits-per-weight efficient inference on edge CPUs. The codebase is publicly available in Microsoft's official repository.

#### Summary
LLM deployment is constrained by memory and compute requirements, and existing quantization approaches struggle to preserve fidelity below 1 bit per weight. LittleBit represents weights via low-rank latent matrix factorization followed by binarization of the resulting factors, and counters information loss through a multi-scale compensation mechanism operating across row, column, and latent dimensions. Effective quantization-aware training is enabled by Dual Sign-Value-Independent Decomposition (Dual-SVID) for initialization and a residual compensation scheme to reduce approximation error.
