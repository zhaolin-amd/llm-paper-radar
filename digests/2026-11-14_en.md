#### Summary
MoE inference on consumer hardware is bottlenecked by weight memory—a 35B model occupies 19.5 GB at 4-bit—and sparsity reduces compute but not the bytes that must be loaded. Naive SSD offloading fails because expert selection for layer N+1 depends on layer N's output, preventing early read issuance. Edge0 introduces a prerouter, a per-layer head that predicts the next layer's routing one token ahead and uses that prediction as the actual routing, allowing SSD reads to overlap with computation. A recovery LoRA trained on the student path compensates for quality loss from both INT4 quantization and routing replacement. On a single 24 GB machine, Edge0 serves a 35B MoE at 20 tok/s within 3 GiB of peak active memory, staying within a few points of the fp16 teacher across five public benchmarks.

- 🎯 Prerouter predicts next-layer routing one token ahead, enabling SSD reads to overlap with compute and hiding offload latency
- 🔧 Recovery LoRA trained on the student path compensates for both INT4 quantization and routing-replacement quality loss
- 📊 Serves a 35B MoE at 20 tok/s with only 3 GiB peak active memory on a single 24 GB machine, near fp16 teacher quality
- 💡 Framework, checkpoints, and adapters are fully open source; an 8B tier runs on the same framework

#### Summary
Weight-activation quantization reduces inference memory and compute but existing methods typically require costly cross-layer optimization and architecture-specific basis-transform propagation. MACaQ is an MXFP4 W4A4 post-training quantization method that treats every linear layer independently, applying a per-channel scale and block-Hadamard transform online to activations while absorbing the inverse transforms into weights, enabling a streaming implementation where only one layer resides in memory at a time. Flip-Refinement, a Hessian-aware coordinate-descent procedure, further improves over round-to-nearest by greedily shifting individual FP4 codes to adjacent representable values. MACaQ incurs only 2.3% end-to-end overhead over pure MXFP4 on Qwen3-32B in vLLM, achieves lower perplexity than DuQuant++ and MR-GPTQ with 11× faster quantization on Llama-3-8B, and quantizes a 122B-parameter model in 64 minutes using only 32.5GB GPU RAM.

- 🎯 Per-layer-independent design: block-Hadamard transform applied online to activations with inverse absorbed into weights, eliminating cross-layer dependencies
- 💡 Flip-Refinement: Hessian-aware coordinate descent greedily moves FP4 codes to adjacent representable values for improved quantization quality
- 📊 Beats DuQuant++ and MR-GPTQ in perplexity; matches best PPL on Llama-3-8B with 11× less quantization time; quantizes 122B model in 64 minutes with 32.5GB GPU RAM
- 🔧 Only 2.3% end-to-end overhead on Qwen3-32B in vLLM; applied without modification to image diffusion models

#### Summary
KV cache memory fragmentation and redundant duplication in LLM serving systems severely limit batch sizes and therefore throughput. PagedAttention addresses this by applying OS-style virtual memory paging to KV cache management, partitioning it into fixed-size blocks that can be allocated and shared flexibly. Built on PagedAttention, vLLM achieves near-zero KV cache memory waste and supports flexible intra- and inter-request KV cache sharing. Compared to state-of-the-art systems such as FasterTransformer and Orca, vLLM delivers 2–4× higher throughput at the same latency level, with greater gains on longer sequences, larger models, and more complex decoding algorithms.

- 🎯 PagedAttention manages KV cache in fixed blocks inspired by OS virtual memory paging, eliminating fragmentation and redundant copies
- 📊 vLLM achieves 2–4× throughput improvement over FasterTransformer and Orca at equal latency
- 💡 Flexible KV cache sharing within and across requests further reduces memory usage beyond fragmentation elimination
- 🔧 Gains are more pronounced with longer sequences, larger models, and more complex decoding algorithms; code is open-source
