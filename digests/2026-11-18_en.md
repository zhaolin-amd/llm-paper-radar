#### Summary
Speculative decoding draft models that read the target's hidden states, such as DFlash and EAGLE-3, conventionally inherit the target's full hidden width. This work shows that the draft's entire residual stream can run at half or a quarter of that width while largely preserving token acceptance rates. For DFlash, the trained output adapter folds into the vocabulary projection, leaving logits unchanged up to floating-point rounding. Evaluated on Qwen3-8B (NVFP4) and GPT-OSS-20B (MXFP4) in SGLang on a B200 and a GB10, narrowing the draft yields 1.06–1.12x end-to-end speedup on B200 and 1.13–1.44x on GB10 at batch size 1, with up to 1.21x gains at larger batch sizes and no narrow draft slower than full width.

- 🔧 Validated in SGLang with NVFP4/MXFP4 quantized targets on both B200 and GB10 GPUs

#### 🧭 Why this paper
**Survey / methodology & comparison** · topic 5/5 · practicality 5/5 · composite 10/10 · This is a rigorous measurement methodology study that directly addresses the core question quantization engineers care about most: when comparing a quantized model against a BF16 baseline, which changes stem from quantization itself versus noise sources such as engine switching, batch size, and kernel selection. It systematically quantifies each noise source on two decision models (9B and 27B) on an NVIDIA GB10—restart reproducibility, engine differences (0–16 flips), batch size (8–15 flips), kernel drift (10–14 flips)—alongside quantization effects (FP8: 1–2%, Q4_K_M: 3.5–5.8% decision flips), and shows that accuracy metrics hide a large portion of individual decision changes. The study is pre-registered with public code and per-record outputs, making it an exemplary empirical comparison methodology for any compression engineer requiring rigorous PTQ scheme evaluation.

#### Summary
Quantization evaluations typically compare a quantized model against its BF16 baseline, but such comparisons simultaneously change the serving engine, server instance, batch size, and kernel selection—none of which are quantization. On an NVIDIA GB10, this work systematically measures decision-flip rates from four non-quantization noise sources (restart reproducibility, engine switching, batch-size changes, kernel drift) across 2,400 public decisions for Clef-flash (9B) and Clef (27B), expressing each quantization effect as the excess above these baselines. Non-quantization sources move at most 0.92% of decisions, while 4-bit formats (Q4_K_M, NVFP4) reach 3.50–5.79% flips and cleanly separate from all noise sources. Accuracy metrics mask most of this: Clef's Q4_K_M build shifts net accuracy by only −0.02 points over 31,275 questions, yet 436 individual decisions worsen.

- 🎯 Isolates four non-quantization noise sources (restart, engine, batch size, kernel) on the same hardware, expressing quantization as excess decision-flip rate
- 📊 Non-quantization noise ceiling: 0.92%; Q8_0: ~0.88–1.04%; FP8: ~1.62–2.12%; Q4_K_M and NVFP4: 3.50–5.79%—4-bit intervals fully separate from all noise sources
- 📊 Accuracy severely underestimates impact: Clef Q4_K_M net effect is −0.02 points, yet 436 decisions worsen; NVFP4 costs Clef-flash 0.95 points and Clef 0.65 points
- ⚠️ Two pre-registered predictions failed: FP8 is not within restart noise, and engine switching flips fewer decisions than 8-bit quantization
