#### 摘要
消费级硬件上的 MoE 推理受制于权重内存：35B 级模型在 4-bit 下占 19.5GB，且稀疏性只减少计算量而不减少需读取的字节数。简单 SSD offloading 无法隐藏 I/O 延迟，因为第 N+1 层的 expert 选择依赖第 N 层的输出，无法提前发起读取。Edge0 引入 prerouter——每层用一个轻量预测头提前一个 token 预测下一层的路由，预测结果直接作为路由决策使用，从而实现流水线式 expert prefetch；配合在 student 路径上训练的 unmerged recovery LoRA 补偿 INT4 量化与路由替换带来的质量损失。在单台 24GB 显存机器上，Edge0 以 3GiB peak active memory 实现 35B MoE 20tok/s 推理，在五项公开 benchmark 上平均性能与 fp16 teacher 相差仅数个百分点。

- 🎯 prerouter 提前一个 token 预测下一层路由，预测即路由，实现 expert I/O 与计算完全流水线化
- 💡 unmerged recovery LoRA 训练于 student 路径，同时补偿 INT4 量化损失与路由替换误差
- 📊 单台 24GB 机器，peak active memory 3GiB，35B MoE 达到 20tok/s，五项 benchmark 与 fp16 差距仅数点
- 🔧 框架、checkpoint 及 adapter 全部开源，支持 8B 和 35B 两档 MoE

#### 摘要

- 💡 TL进一步推广为ELUT（element-wise lookup table），理论与实验均表明对低比特LLM有较大潜力
- 🔧 系统无需校准（data-free），代码开源，面向CPU边缘部署
