* 问题之河

模型一边“想”一边吐出几万个字的时候，它的“草稿纸”（KV cache）会涨到比模型本身还大。能不能把草稿纸上的每个数字只用 2 个比特记下来，而不让模型推理变笨？

难在哪：2 比特只能区分 4 个档位，误差一大，推理链条里一步错、步步错。于是大家转而想“不要所有数字都一样粗糙，把有限的比特花在刀刃上”。可是什么是刀刃？每一代人给的答案都不一样：先是看层，再是看通道的大小，再是看查询（query）要不要用它，最后这篇说要看“成对”的通道。这条河就是“刀刃到底怎么认”的演化史。

* 演化叙事

** 2024 | KIVI 一派: 统一位宽, 但把 key 和 value 区别对待

*** 它看到了什么问题

在它之前，低比特 KV 量化的默认做法是“整块张量用同一个量化尺子”。但 key 里有少数几个通道的数值特别大（离群通道）。尺子要迁就这几个大数，其余通道就被量化成一堆相同的值，信息丢光。

*** 它的解法

key 沿着通道方向分组量化（每个通道自己有一把尺子），value 沿着 token 方向分组量化。再留一小段最近的 token 用 FP16。这一派（KVQuant、GEAR 等也在其中）的共同点是：位宽是统一的，2 bit 就是 2 bit。

*** 为什么这招管用（以及哪里埋了新坑）

给离群通道单独的尺子，这是对症下药。但 PN-Mix 的引言指出这一派的共同缺陷：每个元素用同样的位宽，不管它重不重要，重要成分的误差没人专门控制。在长推理链里误差会累积。2 bit 下推理任务（如 AIME）掉得很厉害，PN-Mix 的表里 KIVI 在 Qwen3-8B 上均分 68.16，FP16 是 77.85。既然所有通道不一样重要，位宽为什么要一样？

** 2025-02 | KVTuner: 按层分配位宽

*** 它看到了什么问题

统一位宽浪费，而且不同层、不同模型对量化的敏感度差别很大。它还观察到 key 整体比 value 更敏感。

*** 它的解法

把“每层用几比特的 key、几比特的 value”当作搜索问题，离线跑多目标优化，找到一组配置，上线时直接用。为了搜索不爆炸，它先剪枝每层的候选、再把行为相似的层聚类。报告在 Llama-3.1-8B-Instruct 上做到近似无损的 3.25 bit，对 Qwen2.5-7B 这类敏感模型则要 4 bit。

*** 为什么这招管用（以及哪里埋了新坑）

把比特按层分配，等于第一次承认“重要性是不均匀的”。但粒度还是太粗：同一层里依然是一刀切；而且它的 3.25 到 4 bit 离“2 bit 级别”还有距离。把刀刃再缩小一圈，到层里面的通道上，会怎样？

** 2025-11 | Kitty: 同一层内, 少数 key 通道升级

*** 它看到了什么问题

层内部同样不均匀。2 bit 在推理上掉点，但 4 bit 基本无损，那么只需要把少数关键 key 通道升到 4 bit，平均位宽仍然接近 2 bit。

*** 它的解法

key 缓存大部分通道 INT2，少数通道升到 INT4；挑选标准是通道的平均幅值（幅值大的升级），这样运行时不用算 MSE。系统上，把混合精度页拆成一张稠密 2 bit 张量加一张结构稀疏的“多出来的 2 bit”张量，用 Triton 页式反量化内核实现。value 按 token 的 INT2，最近一段窗口 FP16。报告 KV 内存近 8 倍压缩，吞吐 2.1x 到 4.1x。

*** 为什么这招管用（以及哪里埋了新坑）

幅值大的通道一旦被量化坏，对 logit 的破坏确实大，所以这个启发式不差。PN-Mix 给它记了三笔账：一是只看 key，不看 query；二是通道被当作各自独立的个体，而 RoPE 其实把相邻两个通道转成一对；三是它按量化组重新选通道，需要存、读每组的索引，解码越长这个开销越大。

** 2025-12 与 2026-04 | MixKVQ 与 ChanMix: 把 query 拉进来 / 把通道分成四档

这两篇与 Kitty 大致同期，不是严格的先后关系，所以放在同一节。

*** 它看到了什么问题

MixKVQ 的摘要说，已有混合精度方案“认不准”哪些部分需要高精度，主张要同时看通道自身的量化难度和它与 query 的相关性。ChanMix（ICLR 2026）则认为通道有不同性格：检索通道和离群通道脆弱、普通通道和次正常通道（subnormal）耐受。

*** 它们的解法

MixKVQ：轻量算法找出需要高精度的 key 通道，即插即用（打分公式的细节我没读到，摘要页没写）。ChanMix：离线标定，找出“检索通道”给 4 bit，离群 3 bit，普通 2 bit，次正常 1 bit，按范围聚类分档，配 8 bit 对齐打包的 Triton 内核。

*** 为什么这招管用（以及哪里埋了新坑）

注意：PN-Mix 的可见正文没有提到 MixKVQ；它把 ChanMix 和 Kitty 当作通道级基线。PN-Mix 对 ChanMix 的批评是：离线标定意味着不随输入变化，打分标准是通道的取值范围而不是对 logit 的影响。两条线剩下的共同毛病：仍然是“单个通道”视角。

** 2026-10 | PN-Mix: 以 RoPE 通道对为单位, 用 query 范数乘 key 范数打分

*** 它看到了什么问题

前面所有通道级方法的盲点：现代大模型都用 RoPE，它把每相邻两个通道当成二维平面上的一个向量来旋转。attention logit 其实是对每个“通道对”求和：query 对范数 乘 key 对范数 乘 两者夹角的余弦。量化既会改 key 对范数，也会改夹角，而误差被 query 对范数放大。所以一个通道对重不重要，要看 query 和 key 两边的范数乘积，只看 key 幅值的方法天然漏掉一半信息。

*** 它的解法

把前面那些方法变形一下：Kitty 的“按 key 平均幅值挑通道”，把“通道”换成“RoPE 通道对”，把“key 幅值”换成“query 对范数期望 乘 key 对范数期望”，你就得到了 PN-Mix 的打分 σ。它把 query 和 key 两边的期望分开算（可分离近似），论文说和精确的联合打分的 Spearman 相关系数为 0.990 到 0.996，前 10% 的重合率 95% 到 96%。

选择只在 prefill 阶段做一次（对 GQA 的多个 query 头取平均），存一张二值掩码，解码全程复用，不再动态重选。选中的通道对用 3 bit，其余 1 bit，再配 1 bit 中点校正（借用 SpeCache 的做法）。前 32 个 sink token 和 128 个 token 的残差缓冲保持 FP16。典型配置 r=50%、G=128，平均 2.26 bit。

*** 为什么这招管用（以及哪里埋了新坑）

直觉：重要性高度集中，论文称前 50% 的通道对占了总重要性的 97% 到 99%，所以把比特给这一半、让另一半只用 1 bit，代价很小。

结果（论文自报）：2.26 bit 下均分与基线 2.32 到 2.39 bit 持平或更好；Qwen3-8B 均分 77.21，FP16 是 77.85，Kitty 是 74.43，KIVI 是 68.16；PolarQuant 在 AIME 上直接归零。Pareto 曲线显示可降到 1.5 bit 才明显掉，基线在 2.25 bit 以下就陡降。消融里去掉 1 bit 校正的损失比去掉 sink 保护更大；在线重选的变体在 Qwen3-8B 的 AIME24 上 72.33，对比一次性选择的 76.00。也就是说，在这个设置里重选并没有更好，反而更差。

新坑（作者自己写的）：只适用于 RoPE 的 decoder-only 模型；效率数据只在单张 A100-40GB 和 Triton 实现上测；batch 相同、FP16 放得下时 FP16 更快。我的补充：prefill 时选出的通道对，是否在很长的解码里（话题漂移后）仍然是刀刃，论文用“重选更差”的消融间接支持，但我没读到更长上下文下的直接证据。

* 洞见

表面上这是“精度分配粒度越来越细”的技术迭代：同一 -> 层 -> 通道 -> 通道对。但深一层看，变化的是“重要性”的定义：从“这个数值大不大”（幅值、范围）转向“这个误差会不会传到 attention logit 上”。KVTuner 开始问敏感度，MixKVQ 把 query 拉进来，PN-Mix 则从 logit 的公式里直接推出该乘什么。打分标准开始贴着下游真正的损失，而不是贴着数据自己的统计特征。

第二个变化是时机：从“解码时不断重选”到“prefill 一次定终身”。PN-Mix 的消融说在这个设置里重选反而更差，这暗示通道的重要性主要由模型结构和 prompt 决定，而不是由逐步生成的内容决定。这是论文数据给的，不是普遍结论。

下一步我的猜测（不确定）：一是把“通道对”推广到别的位置编码（论文自己承认只适用 RoPE）；二是在同一个位宽预算下联合分配 key 通道对和 value、以及层之间的预算；三是在更长的上下文和多轮对话里检验“只选一次”会不会失效。

* 启发

这条线告诉我们怎么找问题：不要只在前人的打分函数上换一个启发式，回到下游的计算公式（这里是 RoPE 之后的 logit 求和），看误差到底是怎么传过去的，打分函数往往能直接读出来。PN-Mix 没有发明新量化器，只是把“看哪里”问对了。

落点在“能用”：这意味着你可以在自己的混合精度 KV 方案里，先用 query 对范数 乘 key 对范数给 RoPE 通道对打分、prefill 时算一次存成掩码，与 Kitty 的幅值标准做对比；也可以拿它的“重选不如不重选”的消融去核对自己场景下动态重选是否值得那份索引开销。
