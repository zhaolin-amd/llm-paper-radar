* 问题是什么

"循环 Transformer"（Looped Transformer，比如 Huginn、Ouro）玩的是一个很划算的
把戏：别造更多参数来加深网络，而是把*同一组权重*反复过几遍——跑 4 遍就等于
有了 4 层的计算深度，但权重只存了 1 份。参数账本上看起来白捡了深度。

但账本上还有一笔没平：每循环一遍，attention 就要产生一份新的 K、V，而且这份
K、V *必须存下来*供后面的 token 用。权重可以共享，K、V 不行——它们是"算出来的
状态"，不是"权重"，每一遍循环都要重新生成、重新缓存。于是出现一个尴尬局面：
参数不随循环次数增长，但显存占用（KV cache）照样随循环次数线性往上涨。深度
"免费"了，但显存账单翻倍地来。

这篇论文（ResidualQuant）要解决的就是这笔账：能不能把"每循环一遍都要存一份
全新 K、V"这件事，压缩到几乎不增加存储？它站在两条前人路线的交叉口——一条是
"把 KV cache 做低比特量化"（这条路上最新最强的是"基于旋转"的方法），一条是
"利用循环之间的相似性直接复用/共享 KV"（这条路是循环 Transformer 专属的架构
技巧）。ResidualQuant 认为两条路都没问到点子上，自己蹚出了第三条。

QuaRot/SpinQuant/RotateKV 之间"逐头优化 attention-aware 旋转 vs 固定/任务

"OptR/OSCAR 具体如何引用/批评 QuaRot"的原文措辞未直接核实，标记为较强推测。
QuaRot/SpinQuant/RotateKV 与 QuIP 之间"把旋转从权重搬到 KV 激活值"这一步，
是基于方法谱系的合理推断（QuaRot 论文确系明确引用 QuIP 的旋转/incoherence
思想），但也未逐字核实 QuaRot 原文批判句。QuIP 对 GPTQ/OPTQ 的关系（"QuIP
不做旋转时退化为更高效的 OPTQ 实现"）来自 QuIP 论文本身的检索结果，确定。
五层中，前五层（GPTQ -> QuIP -> QuaRot系 -> OptR/OSCAR -> ResidualQuant）
找到了明确或高置信度的批判/改进链条，循环 Transformer 架构这条线（Universal
Transformer/ALBERT -> 深度均衡模型 -> Huginn/Ouro）是独立的"问题从哪来"的
背景线索，不是量化方法批判链的一部分，未强行并入溯源地图主线。截至分析时
（2026-10-08），论文发表仅一天，未检索到任何引用或改进它的后续工作，前沿
延伸如实留空。

* 正向费曼叙事：这条线怎么长出来的

** 第 0 步：问题从哪来——循环省了参数, 但显存账单藏不住

Universal Transformer 和 ALBERT 很早就提出"跨层共享权重"：与其每层都存一套
独立参数，不如反复用同一套参数把输入推深。省参数，但推理时每"循环"一遍，
attention 都要重新算出一份 K、V 并存起来。后来 Huginn、Ouro 这类模型把这个
思路做成可调节的"推理时自适应深度"：想让模型算得更深，就多循环几次，不用
重新训练更大的模型。省参数这件事落地了，但 KV cache 要跟着循环次数线性涨——
这不是 bug，是这类架构天生带着的代价，量化社区一直没专门为它设计过方案。

** 第 1 步：GPTQ——先把"怎么量化权重误差最小"这件事谈清楚

在谈 KV cache 之前，LLM 量化这条技术线本身有自己的演化。GPTQ（也叫 OPTQ）
解决的是权重量化：逐列量化权重，每量化完一列就把这一列产生的误差"摊还"给
还没量化的那些列，用二阶信息（Hessian）算出摊还的权重。这套办法很有效，
但它假设权重分布是"规规矩矩"的——如果某几个方向上存在离群值（某些权重或
激活异常大），量化误差会在那几个方向上被放大到失控。

** 第 2 步：QuIP——离群值不是天生的, 把它旋转打散掉

QuIP 看到的问题很直接：与其容忍离群值、小心翼翼地绕开它，不如先用一个随机
正交旋转矩阵，把权重和 Hessian 都"搅拌"一遍。旋转不改变数学上的等价性（乘
一个正交矩阵再乘回它的转置，结果不变），但搅拌之后，原本集中在某几个维度的
离群值被摊匀到了所有维度上——没有哪个方向再显得格外突出，量化误差也就不再
在某几个方向上爆炸。QuIP 甚至证明了：如果不做这个旋转，它的方法会退化成一个
更高效实现版本的 GPTQ。换句话说，旋转就是 GPTQ 的"升级补丁"。但 QuIP 瞄准的
始终是权重，而真正在推理时随着上下文变长、批大小变大而疯狂吃显存的，其实是
KV cache，不是权重本身。

** 第 3 步：QuaRot / SpinQuant / RotateKV——把旋转这把刀, 对准 KV 激活值

这一步的转折是：旋转这个技巧为什么只用在权重上？K、V 本身也是数值，也会有
离群通道，也可以旋转打散。QuaRot 把"旋转 + 无离群值推理"的框架从权重搬到了
整个推理管线，包括 KV 激活值，实现了接近 4-bit 的精度；SpinQuant 进一步把
旋转矩阵从"随机生成"换成"学出来的"，让旋转更贴合具体模型的权重分布；
RotateKV 则专门针对 KV cache 场景打磨旋转方案。这些方法共同把"旋转打散离群值"
确立为 KV 量化里的主流范式，但旋转矩阵本身大多是固定的或者针对整体误差去学的，
没有专门盯着"这个旋转对 attention 最终算出来的输出误差影响多大"去优化。

** 第 4 步：OptR / OSCAR——旋转也该服务于 attention 本身, 但省不掉 BF16 补丁

OptR 和 OSCAR 把旋转这件事做得更"懂 attention"：不再是笼统地让激活值分布
更均匀，而是逐个 attention 头去优化旋转矩阵，直接以"最小化 attention 输出的
误差"为目标函数来求解。这一步让精度能被推到比之前更激进的 INT2。但代价藏在
一个细节里：无论旋转做得多精细，attention sink（序列最开头的几个 token，
它们在很多模型里会吸收异常多的注意力权重）和最近的一小段上下文窗口，依然是
对最终输出误差影响最大的部分，一旦量化，误差会被攻击性地放大。OptR/OSCAR
的解决办法是给这两类 token 开后门——直接保留 BF16 原精度，不量化它们。这是
一个有效但不彻底的补丁：它意味着无论旋转优化得多好，总有一块显存开销是甩
不掉的，而且这块开销的大小和"attention sink + 最近窗口"的绝对 token 数挂钩，
不会随着你想要的压缩比提高而缩小。

** 第 5 步：ResidualQuant——循环 Transformer 有一种旋转方法压根用不到的信息

本文作者的洞察是：OptR/OSCAR 那个 BF16 补丁之所以甩不掉，是因为"纯旋转"这
条路径里，可利用的信息已经用尽了——旋转只能重新排布同一份 KV 内部的数值分布，
没法凭空变出额外信息去压低那部分高敏感度 token 的误差。但循环 Transformer
恰好藏着一份旋转方法完全没用上的免费信息：*同一个 token 在不同循环里产生的
K、V，彼此非常相似*（这背后有深度均衡模型的"不动点"视角撑腰——反复用同一组
权重去逼近一个不动点，自然导致相邻循环的状态变化越来越小）。

于是变形发生了：把"每次循环的 KV 都独立量化，再靠旋转兜底"，换成"只把最后
一次循环的 KV 当作参考基准，完整保留它（INT4 锚点），其余每次循环的 KV 不再
独立存储，而是编码成相对这个参考基准的*差值*"。差值本身数值范围远比原始 KV
小得多——越小越容易用极低比特（INT2）表示而不炸误差。作者在这个差值上还
叠加了最小二乘缩放（把差值的数值范围精确对齐到 INT2 能表示的区间）和旋转
（处理差值内部可能残留的离群通道），外加"循环级混合精度"（不是每次循环都
一刀切用 INT2，根据每次循环和参考循环差异的大小动态分配比特）。最终效果是：
不再需要为 attention sink 或最近窗口开 BF16 后门——因为真正棘手的信息已经
被"参考基准 + 残差"这个结构天然地分担了，敏感的部分可以用相对更高的比特去
捕捉残差，而不需要整段保留原精度。

** 顺手补的一刀：为什么不走"直接复用循环间 KV"这条路

MoR、PLT、MELT 这类方法走的是另一条路：既然循环之间 KV 很像，那干脆直接复用
前一次循环（或共享一份经过门控更新的）KV，连存储都不用分开。ResidualQuant
指出这条路的硬伤：它们是在*架构层面*假设"循环间差异不重要，可以丢掉"，一旦
某次循环的表示因为任务或模型特性而和参考循环产生了明显偏离，这部分被丢掉的
信息就回不来了，精度说崩就崩。而 ResidualQuant 的残差编码不丢信息——哪怕
某次循环和参考循环差得多，这份差异依然被完整地编码进残差里，只是用低比特
量化处理，精度打折但不是信息归零。这也是为什么论文说自己不是"复用 KV"，
而是"用量化的方式榨干循环间冗余"。

* 洞见

** 这条线真正在变的是什么

表面上每一步都在换"旋转施加在哪里、针对什么目标优化"：权重 -> KV激活值 ->
attention 输出误差 -> 循环间残差。但真正在变的是一个更底层的判断：*"离群值/
误差到底该靠'打散重排'来摊平，还是该靠'找一个更好的参考点再编码差值'来消化？"*
GPTQ 到 OptR/OSCAR 这一段，整条线都在同一个范式里内卷——旋转矩阵，不断把
"打散"这件事做得更细致、更懂 attention，但始终没有跳出"每一份 KV 都要独立
被打散、独立被量化"的框架，于是总有几个"旋转也救不了"的硬骨头（sink、
最近窗口）需要开后门。ResidualQuant 的跳出点是：不再问"怎么把这一份 KV
打散得更均匀"，而是问"这一份 KV 和另一份已经几乎一样的 KV 之间，差值有
多大"。这是把"量化单个信号"换成了"量化信号之间的冗余"——跟视频编码里
"不存每一帧的完整画面，存关键帧 + 帧间差值"是同一个思路，只不过这里的
"帧"是循环，"关键帧"是最后一次循环的 KV。这提醒了一件事：旋转打散是一种
"假设没有额外结构可用"时的通用兜底方案，一旦某个场景天然带着额外结构（循环
间相似性、视频帧间相似性……），更划算的做法往往是先利用结构把问题变小，
再谈量化精度，而不是指望量化方法本身越做越精细地去硬啃一个本可以先被结构
消解掉的难题。

** 下一步最可能往哪走

- ResidualQuant 的参考基准固定选在"最后一次循环"，这个选择对"循环次数
  固定、提前知道会循环多少次"的推理场景友好，但如果循环次数是运行时自适应
  决定的（像 Huginn 那样按置信度提前退出），"最后一次循环"事先并不知道是
  第几次——参考基准该怎么动态选取，是一个论文没有展开的真实缝隙。
- 残差编码本身假设循环间差异整体偏小，但没有排除某些任务（比如需要在循环
  间维持显著不同中间状态的复杂推理任务）里差异本身就大的情况——如果残差
  分布本身就是"厚尾"的，INT2 残差还能不能扛住，论文的 mixed-precision
  设计只是按循环粒度分配比特，没有按 token 粒度去适配。
- 这条量化线和"循环间 KV 复用"那条架构线原则上可以叠加（比如对复用后仍
  需要保留的那部分差异信息做残差量化），但两者结合的工程复杂度和收益还
  没有人验证过。

* 红线自检

- 问题为轴：全文围绕"循环 Transformer 的 KV cache 该如何压缩"这一条线索
  展开，GPTQ/QuIP/QuaRot/OptR 等论文只是量化这条技术脉络上的站点。
- 口语检验：旋转比作"打散离群值"，残差编码比作"视频关键帧+帧间差值"，
