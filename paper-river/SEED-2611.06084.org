* 问题之河

混合模型（少数几层 softmax 注意力 + 大量线性注意力/状态空间层）已经不用存巨大的 KV cache 了，为什么服务起来还是又贵又占显存？

难点在于：每个循环层都要给每个 token 留一份“记忆”，prefill 时每个 token 都得走完全部深度；decode 时每层还要背一个完整的状态矩阵。省了 KV cache，却把账转到了“深度算力”和“状态带宽”上。

*诚实说明*：本文只读了摘要页，没有读正文、引言、相关工作，也没有做逐篇引用核对和后续论文搜索。下面的前序链条是根据摘要里点名的方法（Gated DeltaNet、Kimi Delta Attention、Mamba-2）和领域常识推断的，不是论文自己声明的批判链，标为“推测”。

* 演化叙事

** 推测 | 混合架构: 用固定大小的状态换掉不断增长的 KV cache

*** 它看到了什么问题
纯 softmax 注意力的 KV cache 随长度涨，长上下文服务被显存和带宽卡住。

*** 它的解法
大部分层换成线性注意力或状态空间层：每层只留一个固定大小的状态，像一本不会变厚的笔记本，读新内容就边读边改写这本笔记。留几层 softmax 注意力保住精确召回。

*** 为什么这招管用（以及哪里埋了新坑）
KV cache 的增长问题缓解了。但摘要说的新坑是：每层仍然给每个 token 写记忆，而且 prefill 的深度算力、状态的存储都没省。（这一段的具体论文关系是推测，来自摘要对模型家族的描述。）

** 2026 | SEED: 浅层编码, 深层记忆

*** 它看到了什么问题
摘要给出两个观察：
1. *写比读容易*。给深层产生“某 token 的记忆”，所需的深度计算远少于预测下一个 token。所以不必让每个 prompt token 走完所有层。
2. *状态沉降 (state sink)*。每个头的循环状态，大部分能量集中在一个固定方向的秩一项上，剩下的才是低秩的“工作记忆”。

*** 它的解法
把这两个观察分别变成两个动作。
- 浅 prefill：训练“emitter”，也就是深层写路径的副本，从一个较浅的锚点层的残差流直接填出深层记忆。除最后一个 token 外，其余 prompt token 最少只走 63% 的层。
- 浅 decode 状态：每个状态存成“sink + 低秩因子”，Gated DeltaNet、Kimi Delta Attention、Mamba-2 的更新可以精确地在这个因子形式上做。周期性重新压到低秩，作者证明了开环误差有界，与压缩次数无关。

如果把完整状态去掉，只留固定方向那项再加一小块低秩，你就得到了 SEED 的 decode 状态。

*** 为什么这招管用（以及哪里埋了新坑）
直觉：深层“写”的信息大多已经能在浅层残差里读出，状态的能量又集中在少数方向。摘要说的边界：权重冻结，不压缩注意力 cache，每个生成 token 仍然跑全部层。所以收益集中在 prefill 和状态存储，不在 decode 的深度。结果：五个生产级 hybrid、六个 checkpoint（30B 到 300B+），在十一项官方考试上近乎无损；SGLang + NVIDIA GB300 上跑 agentic coding trace，Qwen3.8-Flash-Next 的单 GPU 吞吐提升 1.2-1.4 倍。

* 洞见

表面是“又一个加速方法”，更深的变化是：大家开始把模型内部的不对称拿来用。写比读便宜、状态能量集中在一个方向，这是训练出来的结构，不是人为设计的，SEED 是把它测出来再利用。下一步可能是同样的思路往 decode 深度走，或者扩到 attention cache，不过这是我的推测，摘要没有提。

* 启发

做推理优化时，先测“这一步到底需要多少深度/多少秩”，往往比重新设计结构更省事。能用的地方：任何有循环状态的模型，先看状态能量谱，看是否有固定主方向。另外，读到这类论文时，要先区分“论文自己声称的批判链”和“我根据领域补的链”，本文的前序部分属于后者。
