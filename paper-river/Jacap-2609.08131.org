* 问题之河

上一篇（CapKV）已经把 KV cache 驱逐这件事，从"一堆各显神通的 heuristic"统一成了"最大化保留信息容量"的一个闭式公式。故事本该到此为止——可这份公式里悄悄埋了一个假设：*attention 是线性的*。

问题是，attention 根本不是线性的。它的核心操作是 softmax——一个会"抢注意力"的非线性开关：某个 token 一旦 logit 稍微高一点，softmax 会把它的权重越推越大，同时把别人的权重压得更低。这种"赢家通吃"的竞争关系，线性模型完全看不见。

于是新问题浮现：*当你用一个明知道是错的线性公式去指导驱逐决策，你到底丢掉了多少信息？* 能不能把这个被简化掉的"非线性"找回来，同时还保留公式能算的优点？

** 2026-04 | CapKV: 母公式——但假设了一个不存在的线性世界

*** 它看到了什么问题

前五年的 KV 驱逐方法各自为战：H2O 看历史累计注意力，SnapKV 看末窗口注意力，Knorm 看 key 范数，KeyDiff 看 key 之间的差异，Expected Attention 预测未来注意力分布。没人说得清它们到底在优化同一件事，还是各追各的。

*** 它的解法

把 KV cache 建模成"一组通信信道"：每个 (key, value) 对负责把未来 query 的信息传给 attention 输出。为了让"保留了多少信息"这件事能算出闭式解，CapKV 做了一个关键的简化——*假设这条信道是线性、高斯的*：输出直接等于 query 乘一个固定矩阵，加高斯噪声。在这个假设下，容量退化成一个漂亮的 log-determinant 公式，Knorm、KeyDiff、SnapKV 全部可以在这个公式下被重新推导出来，作为它的不同近似。

*** 为什么这招管用（以及哪里埋了新坑）

管用，是因为它第一次让整个领域"知道自己在优化什么"。但作者自己也承认：线性-高斯只是一个"作图工具"，真实的 attention 计算里有 softmax。

具体的坑在这里：softmax 会做*归一化竞争*——一个 token 的输出权重不只取决于它自己的 logit，还取决于它跟同一批被保留 token 的相对大小。CapKV 的线性公式把"query 到输出"看成一个固定矩阵乘法，完全忽略了这种此消彼长的竞争关系。这在压缩比不高时问题不大（保留的 token 够多，竞争被稀释），但*一旦压缩比冲到 90% 以上*，剩下的少数几个 token 之间的 softmax 竞争会变得异常剧烈——留下两个内容相近但都"看起来重要"的 token，可能比留一个更划算的组合还差，而线性公式看不出这一点。

这就是 Jacap 要补的洞。

** 2026-09 | Jacap: 把 softmax 的"抢戏"找回来

*** 它看到了什么问题

CapKV 的线性代理把 attention 映射写成 f(q) = U · (Kq)，一个固定矩阵乘法。但真实的 attention 是 f(q) = U · softmax(Kq/√d)——多了一层非线性归一化。

这层非线性不是无关紧要的装饰。softmax 的本质是"竞争"：如果某个被保留的 key 已经和 query 高度对齐（大 logit），softmax 会把它的权重推到接近 1，同时几乎"没收"其他 key 的权重——即使那些 key 本身也和 query 有一定关联。这种赢家通吃的动态，线性模型完全建模不了，因为线性模型里每个 key 的贡献是独立叠加的，不存在"抢"这回事。

作者的判断是：*在低压缩比下，这个误差可以忽略；但在高压缩比下——恰恰是 KV 驱逐最需要精确决策的场景——这个误差会被放大成实打实的性能差距*。

*** 它的解法

思路上做一个很直接的变形：*不再把非线性 attention 硬套成线性模型，而是围绕"当前这批 query 大概长什么样"这个局部点，把非线性函数做一阶泰勒展开*。

具体来说：假设未来 query 集中在某个分布中心 μ_Q 附近波动。在 μ_Q 这一点，softmax(Kq/√d) 这个非线性函数其实是可以局部线性化的——它的"局部斜率"就是数学上的 *Jacobian 矩阵*。这个 Jacobian 恰好可以拆成三块：

- key 的可达性（哪些 key 跟 query 对齐）
- 一个"softmax 竞争矩阵" S_C——它的对角线告诉你每个 token 的注意力对自己 logit 有多敏感，非对角线则编码了 token 之间"此消彼长"的竞争
- query 统计量（未来 query 大概怎么分布）

把这个局部 Jacobian 当成"有效信道增益"塞回 CapKV 的容量公式里，就得到了 *Jacobian Information Capacity*——形式上和 CapKV 的公式长得很像（还是 log-determinant），但里面多了一个只有非线性模型才有的"软max 竞争"项。

一句话概括这次变形：*如果你把 CapKV 的固定矩阵 K_C 换成"围绕当前 query 中心局部线性化后的有效矩阵 J_C = U_C · S_C · K_C"，你就从线性容量走到了非线性容量*——多出来的 S_C 就是之前被线性假设抹掉的 softmax 竞争。

工程上，直接对这个理论公式做优化太贵（要对每个候选子集求矩阵行列式）。于是 Jacap 只保留 S_C 的对角线（每个 token 自己的 softmax 敏感度 ρ_i = ᾱ_i(1-ᾱ_i)），忽略 token 间的非对角耦合，换来一个可以像 CapKV 一样一次扫描、用杠杆分数贪心选取的实用算法。

*** 为什么这招管用（以及哪里埋了新坑）

管用的关键在于 ρ_i = ᾱ_i(1-ᾱ_i) 这一项——它是个"钟形"函数：注意力权重接近 0 或接近 1 的 token，敏感度都低（前者是"从没被看见过"，后者是"已经赢麻了，再涨也涨不动"）；只有*注意力权重处于中间地带*的 token，敏感度才最高。这恰恰纠正了纯注意力分数方法（H2O、SnapKV）的一个隐藏偏见——它们只看"分数高不高"，却看不出"分数还有没有边际信息量"。Jacap 相当于告诉你：*不要只留分数最高的，要留"还没被 softmax 判死刑、仍有摇摆空间"的*。

实验上，这一改动在压缩比适中（0.75）时和 CapKV 打平或略赢，但在压缩比极高（0.9）时领先第二名约 5 个百分点——正好印证了作者的判断：线性近似的误差是随压缩比放大的，越"逼到墙角"，非线性建模的价值越大。

坑还在：

- 工程近似只保留了 S_C 的对角线，扔掉了 token 之间的非对角竞争项——也就是说，*"A 和 B 谁更该被留下"这种成对竞争关系，理论上被建模了，实践中又被砍掉了*。真正利用非对角项的算法还没人做。
- μ_Q、Λ_Q（未来 query 的分布中心和协方差）仍然是从*历史*已经观察到的 query 里估计出来的——本质上还是"用过去预测未来"，一旦分布发生突变（比如用户突然换了个完全不同的任务），这个局部线性化的中心点会失效。
- 一阶泰勒展开只在 μ_Q 附近"局部"成立。如果未来 query 的波动范围 Λ_Q 很大（分布很分散），一阶近似本身就会失真——这篇论文没有讨论"什么时候局部线性化会崩"。

* 前沿延伸

Jacap 于 2026 年 9 月 8 日提交，截至本文写作（次日）尚未检索到任何明确建立在它之上的后续论文，也在情理之中——发布时间太短。诚实地说：*这条线目前的最新进展就是 Jacap 本身*。

可以预判的方向（仅为推测，非已发生的引用关系）：

- *补上非对角竞争项*：Jacap 主动舍弃的 token-token 非对角耦合，理论上是这次变形里最有信息量、但也最贵的部分。谁能把它高效地纳入选择算法，谁就补上 Jacap 自己指出的坑。
- *动态/流式化*：和 CapKV 一样，Jacap 仍是一次性 (one-shot) 选取，μ_Q 从历史估计。decoding 推进时局部线性化中心的滚动更新，是两代论文共同留下的空白。
- *二阶展开*：如果一阶 Jacobian 已经能在高压缩比下赢 5 个点，二阶项（Hessian）会不会在极端压缩（比如 0.95+）下继续放大优势，还是收益迅速递减？

* 洞见

这一步和上一步（CapKV 统一各路 heuristic）性质不同——CapKV 是"归纳"：把散落的经验规则收进一个公式；Jacap 是"证伪-修正"：指出这个公式本身的一个建模假设是错的，然后精确定位误差来源、量化它、再补上去。这是理论工作走向成熟的典型第二步：先有一个能用的简化模型统一现象，再有人回头问"这个简化到底丢了什么，丢的东西什么时候要命"。

更值得注意的是 Jacap 精确定位了"简化模型什么时候会失效"——不是笼统地说"线性假设不精确"，而是具体指出*高压缩比*是误差被放大的场景。这比"我们的方法更精确"这种笼统说法有价值得多：它把"什么时候该用更贵的非线性模型、什么时候线性代理就够用"变成了一个可以按压缩比决策的工程问题，而不是"总是用更复杂模型"的教条。

下一步最可能的方向，我倾向于押注在"把舍弃的非对角竞争项拿回来"——因为这恰好是 Jacap 自己在论文里明确留白、且理论已经写清楚只是没工程化的部分，是全篇最低垂的果实。

* 启发

对做研究的人，这一步（相对上一步）给出一条具体、可复用的套路：

*找一个被广泛使用的简化假设，问它哪一层现实被简化掉了，再问这层现实什么时候会反咬一口*。CapKV 用线性-高斯换来了闭式解——这是全领域默认接受的代价。Jacap 没有推翻这个代价，而是精确指出"softmax 的竞争"是这次简化里被丢掉的具体一层现实，并且论证了"高压缩比"就是这层现实反咬一口的场景。

落点在"能用"：当你看到一个领域里所有人都在用同一个简化假设（线性化、独立性假设、正态假设……）时，不要急着换个更复杂的模型去"整体超越"，而是先问：*这个假设丢掉的那一层东西，在什么极端场景下会变得举足轻重？* 找到那个场景，再针对性地把丢掉的那一层局部找回来——往往比推倒重来更省力，也更容易在实验里证明"为什么我行"。
