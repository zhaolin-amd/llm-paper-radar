* 问题之河

KV cache 淘汰（eviction）要在模型还没写出回答之前，就决定哪些历史 token 可以扔掉。可问题是：你要扔的是"将来会不会被问到"的记忆，但你此刻连"将来会被问什么"都不知道。

这个问题卡在两条线上，而且两条线各卡了快三年：

第一条线是"扔的标准对不对"——早期方法只看"读 prompt 的时候谁被注意到了"，却忽略了一个事实：被注意到（attention 高）不等于删掉它有影响（因为还要看它的 value 向量长什么样）。

第二条线是"标准对的时间点不对"——就算标准完全正确，你用来打分的"问题"也是 prompt 阶段的问题，而真正要考的是生成阶段的问题，二者经常对不上号。

一代一代论文前赴后继，是因为这两条线各自有"理论上更对但代价更高"的解法，而把两条线的"更对"同时做到、还不让代价失控，恰好是这篇目标论文想解决的事。

* 演化叙事

** 2023 | H2O: 用累积 attention 决定留谁

*** 它看到了什么问题
KV cache 随上下文变长线性增长，长文本推理内存爆炸。之前的办法要么全存，要么用固定规则（比如只存最近的 token）。

*** 它的解法
把每个 token 在历史上被关注的 attention 权重累积起来，谁的累积分高就留谁——本质是"这个 token 历史上多重要"。

*** 为什么这招管用（以及哪里埋了新坑）
简单有效，比固定规则聪明。但累积分数会随着序列变长而失真——早期偶然被多看了几眼的 token 会一直占着高分，而且这个分数完全是"读 prompt 阶段"算出来的，没考虑后面真正要回答什么。

** 2024 | SnapKV: 只看 prompt 末尾一小段窗口

*** 它看到了什么问题
H2O 的累积分数会被早期噪声污染，而且不稳定。

*** 它的解法
不再累积整个历史，只用 prompt 最后一小段"观察窗口"的 attention 情况来代表这个 token 重不重要——离回答最近的注意力模式最有参考价值。

*** 为什么这招管用（以及哪里埋了新坑）
比累积分数稳定、便宜。但本质上还是"用读 prompt 时的注意力去猜回答时的需求"——这里有两个独立的坑：(1) attention 高不代表删掉影响大，没看 value 向量的内容；(2) prompt 阶段的注意力模式和真正生成阶段要用的 query 可能完全不一样。这两个坑各自催生了一条后续研究线。

** 2025 | OBCache: 光看 attention 不够，要算"删了会变多少"

*** 它看到了什么问题
攻克坑(1)：H2O/SnapKV 这类方法本质是"attention 分数高就留"，但这是个启发式——它们从没真正衡量"如果删掉这个 token，模型的输出会变多少"。

*** 它的解法
借用神经网络剪枝里的 Optimal Brain Damage 思路，把 KV 淘汰看成一个结构化剪枝问题：用二阶泰勒展开，给每个 token 推导出删除后 attention 输出会扰动多少的闭式公式，同时考虑 key 和 value 的贡献。

*** 为什么这招管用（以及哪里埋了新坑）
这是第一次把"删除影响"量化成了真正的理论公式，而不是用 attention 分数打马虎眼。但公式只告诉你"扰动有多大"，没告诉你"往哪个方向扰动最要命"——如果能找到一个更聪明的"参照方向"，还能再榨出一些精度。

** 2025 | AnDPro: 把删除影响投影到"锚点方向"上

*** 它看到了什么问题
OBCache 式的扰动量化是对的，但还可以更精确：删除同样大小的扰动，如果扰动方向恰好偏离了模型真正关心的方向，影响其实没那么大；反之如果扰动方向正好撞在关键方向上，影响就被低估了。

*** 它的解法
把"删除前的 attention 输出方向"当作一个锚点方向，让每个候选 token 的 value 向量往这个锚点方向上投影，用投影长度（而不是原始扰动大小）来打分——分数变成 attention 权重乘以 value 在锚点方向上的投影。

*** 为什么这招管用（以及哪里埋了新坑）
在 16 个 LongBench 任务上，用极小的 cache 预算就保住了 96% 的全量精度，是这条打分线当时的最优解。但 AnDPro 这套"锚点方向"算的仍然是 prompt 窗口的 query 产生的锚点——它完美回答了坑(1)，却完全没碰坑(2)：锚点方向本身还是基于 prompt 阶段的信息算出来的，而不是生成阶段真正会用到的 query。

** 2025 | LAQ / LAQ++: 先偷跑一段草稿，再看草稿要什么

*** 它看到了什么问题
攻克坑(2)：无论打分公式多精确，如果打分用的"问题"（query）本身就是 prompt 阶段的，那估计的"重要性"从根上就可能文不对题——真正的生成阶段会问完全不同的问题。

*** 它的解法
先用一个便宜的策略（比如 SnapKV）跑一段低成本的草稿回答，哪怕这段草稿答案本身是错的也没关系——关键是草稿生成过程中用到的 query 状态，拿这些"真实生成出来的 query"去反过来决定该留哪些 KV。LAQ++ 还把这套 lookahead query 和 prompt 本地 query 结合起来用。

*** 为什么这招管用（以及哪里埋了新坑）
作者发现一个反直觉的现象：草稿答案对不对根本不重要，草稿过程里产生的 query 状态照样能定位到真正该留的 KV。这说明"用真实生成的 query 反推重要性"这个方向是对的。但代价很大——要真的多做一次完整解码生成草稿，推理延迟和显存峰值都明显增加，这成了下一步要解决的"效率"问题。

** 2026 | LookaheadKV / DapQ: 不真的生成，用预测/构造的伪 query 代替

*** 它看到了什么问题
LAQ 的"真草稿"路线效果好，但代价太高——多生成一段完整响应，等于推理延迟翻倍，显存还会出现峰值。

*** 它的解法
LookaheadKV 训练一个轻量预测器，直接"猜"未来会用到的 query 状态，不需要真的跑一遍解码；DapQ 则构造"位置感知"的伪 query，用几何近似代替真实生成。

*** 为什么这招管用（以及哪里埋了新坑）
两者都把 LAQ 的"真实但昂贵"换成了"便宜但近似"——本质是用一次确定性的猜测，替代一次真实采样。但这里留了一个新问题：无论是学出来的预测器还是构造出来的伪 query，都只给出*一个*点估计，而真正的未来其实有很多种可能的走向（模型在同一个 prompt 下可能生成完全不同风格的回答）。用一个点去代表一个分布，天然会有偏差——而且偏差没法量化，因为你根本不知道这一个样本离真实分布有多远。

** 2026-10 | LORE-KV（目标论文）: 别猜了，真的采样一堆未来，再按可靠性加权平均

*** 它看到了什么问题
把前面两条线的局限摆在一起看：OBCache/AnDPro 把"打分标准"做对了，但打分用的 query 还停留在 prompt 阶段或者单一草稿/单一伪 query；LAQ 式的"真草稿"方向对了，但只生成一条轨迹，等于用一个样本代表整个未来分布，而且代价集中在一次里；LookaheadKV/DapQ 为了省成本放弃了"真实采样"，换来的是近似误差没法控制。核心矛盾是：没人把"未来有很多种可能"这件事当成一个真正的分布问题来处理。

*** 它的解法
LORE-KV 把"淘汰该留谁"重新表述成一个对"未来可能的生成轨迹"做分布估计的问题：从冻结的目标模型本身采样 M 条短的自回归续写（不是一条，不是预测出来的，是真的让模型自己往下走几步），每条续写里用到的 query 状态都拿来打分——打分公式直接借用 AnDPro 式的投影思路，但换成"留一法"（leave-one-out）版本：算每个候选 token 如果被删掉，attention 输出在残差流里会扰动多少（经过输出投影矩阵之后的扰动范数平方）。多条轨迹的分数不是简单平均，而是先给每条轨迹算一个"可靠性权重"——轨迹本身的对数似然减去上下文不确定性（熵），再减去和其他轨迹的分歧程度，三项合成一个 soft weight，越典型、越确定、越和大家一致的轨迹权重越大。打完分之后，这些临时续写的 KV 全部丢弃，只留下压缩后的真实 cache 进入正式解码。

*** 为什么这招管用（以及哪里埋了新坑）
这招管用的直觉是：与其用一个样本或一次猜测去赌未来长什么样，不如真的抽几个样本出来做蒙特卡洛估计——论文的消融实验显示，B=128 时单条续写就能拿到相对全部收益的 89%，多条续写带来的增量收益递减但仍然存在，说明"多个未来"确实比"一个未来"更接近真实分布，验证了问题诊断是对的。但新坑也很明显：M 条续写意味着 M 倍的额外前向计算，是一次性压缩开销（相比 AnDPro 慢 1.46-2.77 倍），而且随着 cache 预算变大，这套机制带来的收益会萎缩，甚至在个别任务上出现和baseline比反而掉分的情况——相当于用"确定性换来的效率"换回了"真实性但更贵的计算"，这笔账在大预算场景下未必划算。这也是这篇论文自己坦承的局限，而不是藏起来的问题。

* 前沿延伸

LORE-KV 发表于 2026 年 10 月 6 日，距今（2026-10-07）只有一天，尚未检索到明确引用或批评它的后续工作。诚实地说：这条线目前走到 LORE-KV 为止，是"蒙特卡洛多轨迹估计"这个思路在 KV 淘汰问题上的最新尝试。

可以预见的下一个坑（论文自己也点出来了）：M 条续写的计算开销能不能像 LAQ → LookaheadKV/DapQ 那样被"蒸馏"成一个便宜的近似？如果能学出一个轻量模型，直接预测"多条轨迹加权平均之后的分数"，而不用真的采样 M 次，那就是把 LAQ 系（真实但贵）和 LookaheadKV/DapQ 系（便宜但偏）这两条此前分叉的路线，在"蒙特卡洛集成"这一层上重新合并一次。

* 洞见

这条线真正在发生的变化，不是"分数公式越来越复杂"，而是对"重要性"这个概念本身的理解在升级：从"历史上被注意到过"（H2O），到"删掉会让输出变多少"（OBCache/AnDPro），到"要对的是生成阶段的需求，不是读prompt阶段的需求"（LAQ），再到"生成阶段的需求不是一个点，是一个分布"（LORE-KV）。每一步都是在把"重要性"这个模糊词，往更接近"这个 token 对最终答案的因果贡献"这个真问题上靠近一步。

同时有一条隐藏的代价曲线：越逼近真问题，付出的计算成本越高（H2O 几乎免费 → OBCache/AnDPro 需要额外的投影计算 → LAQ 需要一次完整解码 → LORE-KV 需要 M 次解码）。LookaheadKV/DapQ 证明了"用近似换回成本"是可行路径，但 LORE-KV 选择了反方向——先把"精确但贵"的上限探出来，再留给后人去压缩。这是研究上常见的节奏：先有人证明"做对了能到多好"，再有人想办法把"做对"的代价打下来。

下一步最可能的方向：把 LORE-KV 的蒙特卡洛集成思想和 LookaheadKV/DapQ 的"预测代替采样"结合——学一个轻量模型去预测"M 条轨迹加权平均后大概长什么样"，而不是真的跑 M 次解码。

* 启发

这条演化线提示一种找科研问题的方法：当你发现一个领域里的"最优方法"是靠一个单点估计（one sample/one draft/one anchor）去代表一个本质上是分布的量时，"把它换成蒙特卡洛/集成"几乎总能再挤出一点精度——代价是计算开销线性增长。这意味着你可以：拿到任何一个"用单次前向/单个样本去估计未来"的现有方法，先问一句"这里的未来真的只有一种可能吗？"，如果答案是"不”，那么"采样多个、加权平均"就是一个几乎必然能生效、却常常被前人因为怕贵而没做的改进方向。
