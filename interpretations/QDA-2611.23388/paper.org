#+source: https://arxiv.org/abs/2611.23388
#+filetags: :paper:story:

* 主角
一个量化工程师。每次新模型发布，他都要回答同一个问题：这次该用 GPTQ、AWQ、旋转、还是它们的某种叠加？校准数据用什么？scale 怎么调？

* 困境
没有通吃的配方。同一个模型 4-bit 时 AWQ 赢、3-bit 时 GPTQ 赢；同一个小技巧让一个模型涨 5 点，让另外三个掉点。半年发布 90 多个 10B+ 开源模型，四种精度要 360 多份配方，靠人写不过来。

更糟的是"试一次"太贵。推理模型要写几万 token 的思考链，还要采样很多次才压住噪声：评一个量化 checkpoint 要 23–86 GPU·h。一次搜索只够试几个候选。

* 旧路
- 早期 AutoML（AMC、HAQ、APQ）：自动搜每层 bit 宽，但验证集便宜，搜的空间也只有 bit 宽。
- AMQ、EvoPress：搜每层 bit 宽，EvoPress 用 KL，但 KL 是在拼接模型上测的，不是最终部署的 checkpoint。
- 工具链（ModelOpt、llm-compressor）：人预先写好配方；ModelOpt 的 recipe-search skill 让 agent 在内置选项里选，不写新方法。
- ParoQuant、GSQ：各赢一块，换模型换精度就不是最优；ParoQuant 还要在线旋转和定制 kernel。

* 转折
把"人写配方"换成"agent 写配方"本身并不新鲜——真正的转折是意识到限制 agent 的不是智能，而是两个基础设施瓶颈：
1. 评估信号：要一个**便宜、代表整个部署模型、且 agent 作弊不了**的分数。
2. 搭建零件：要一批**能互相叠加、能自动适配新架构**的 PTQ 方法。

* 解法
** 评估：KL + 长生成
用量化模型与原模型在"原模型自己写的推理轨迹"上的逐 token KL 当分数。它在 vLLM 里、用真实 kernel 算，所以连 kernel 引入的 FP8 scale 误差也被看见；比逐层重构误差更能预测最终精度（82% vs 73%）。分钟级、便宜 350–990×。

KL 看不到的失败（后期循环、不收尾）靠第二个信号补：让 agent 自己挑难题生成完整答案，数"错、循环、被截断"。两个信号一起决定下一步改什么。

** 搭建：统一接口的库
21 个方法都是"checkpoint 进、checkpoint 出"，任意顺序叠加；层间依赖自动推导；专家批量 GPTQ 把 16 GPU·h 降到 0.42。

** 防作弊：agent 看不见评估器
沙箱无 GPU 无网络，只有四条命令；reference traces 与测试集不可见，可读文件预先扫描测试题。因为若 agent 能读到，它会直接在评估数据上校准，KL 降了模型没变好。

** agent 自己做了什么
所有最终配方都用自己选的 prompt 生成校准数据；12 个里 10 个用量化模型自己的回答做训练；5 个还留下了自己写的训练/合并代码；能看日志诊断（把 distillation loss 尖峰追到 BF16 scale 跨过舍入边界、把 R1-Llama W3A16 的零梯度 scale 修掉、在 W4A8 因 FP8 scale 最小步长≥6% 而主动跳过 distillation）。

* 结局
四个推理模型上相对最强公开配方平均 +0.9 / +1.4 / +2.2 pt（W4A16 / W4A8 / W3A16），无推理开销；320B 的 GLM-5.3-Flash NVFP4 W4A4 恢复 98.3% FP8 精度（厂商 96.9% / 96.3%）。每次搜索 64 GPU·h + $19–75 token。反面：同一个 agent 用 ModelOpt 低 0.5–1.3 pt，说明 agent 不是全部。

* 内核
"量化"的单位从"一个算法"变成"一份可搜索的配方"。算法已经够多，缺的是在每个模型上选择与组合它们的机制；这个机制要成立，靠的是**便宜且不被刷分的评估信号**和**可组合的零件库**，而不是搜索算法本身。
