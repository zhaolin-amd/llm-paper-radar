* 一句话
QDA（MIT / NVIDIA，Song Han 组）：让 Claude Code（Opus 5.5）当"量化配方工程师"——每个「模型×精度」跑一次 8 GPU × 8 小时（64 GPU·h）的搜索，用「输出 KL」代替耗时数十 GPU·h 的真实评测，产出的 checkpoint 仍是标准 GPTQ/AWQ/NVFP4 格式，零推理开销。

* 动机（§1、§3）
- 最优配方因模型、精度而异：W4A16 下 Qwen3.5-9B 最好是 ParoQuant，Qwen3.8-27B 是 AWQ，R1-Llama-8B 是 GPTQ；同一个 Qwen3.5-9B 上 AWQ 在 4-bit 比 GPTQ 高 5.1 pt，3-bit 反而低 12.3 pt。
- FP8-aware GPTQ（按 kernel 实际存的 FP8 scale 选码）让 Qwen3.5-9B +5.3 pt，却让其余三个模型掉点。
- 评测太贵：推理模型长 CoT + 多次采样，一个 checkpoint 完整评测 23–86 GPU·h，搜索只能试几个候选。
- 搭建太慢：方法散落在研究代码里，换架构（线性注意力混合、细粒度 MoE）要手工移植；llm-compressor 对 Qwen3-Next 花了三周；256 专家的 Qwen3.6-35B-A3B 一次 GPTQ 要约 16 GPU·h。

* 方法（§4–§5）
** 闭环
(1) agent 写配方 → (2) 库构建 checkpoint → (3) evaluator 打 KL 分（分钟级）→ (4) 对少数候选做长生成检查（repetition loop、截断）→ 预算耗尽后只提交一个 checkpoint 去跑真实 benchmark。

** KL 代理
- 在原模型自己写的 reference traces（数学/科学/代码/写作规划，与测试集不重叠）上，逐 token 计算 KL(p_M ‖ p_x)，且在 vLLM 里用实际 serving kernel 计算，因此连 W4A8 的 FP8 scale 误差也算进去。
- 为省存储只缓存原模型 top-128 token + 一个"其余"桶；Proposition 1：该估计不超过完整 KL（log-sum 不等式，桶合并只会降低 KL），实测低 0–0.4%。
- 验证：44 对 checkpoint，KL 与真实精度排序一致 82%，逐层重构误差只有 73%。成本比完整评测便宜 350–990×。
- tie 判定：重建同一配方（换随机校准子集）KL 的相对标准差 σ=0.5–1.6%，差异小于 σ 就标 tie，防止 agent 追噪声。

** 长生成检查
KL 只能看到前缀条件下的单步分布，看不到晚期才出现的循环。例子：Qwen3.6-35B-A3B W4A16，自生成数据校准 GPTQ 使 KL 降 30%，但 191 道题里 12 道被截断（原模型 3 道），多数是代码题陷入 debug 循环。agent 随后自己生成 600 条难题的长答案，用量化模型自己的 1200 条长答案做 scale distillation，最终比最佳公开配方高 1.3 pt。

** 组合库（21 个 PTQ 方法）
- 扩展 llm-compressor：每个方法"输入量化 checkpoint → 输出量化 checkpoint"，可任意叠加。
- 层间依赖（哪个 norm 喂哪些线性层）从模型自动推导并数值校验，不再硬编码；新架构 GLM-5.3-Flash（288 专家）只要 72 行 adapter。
- 码选择对齐 kernel 实际存储的 scale 精度；专家批量 GPTQ（stack Hessian 统计，一次批量分解）16 → 0.42 GPU·h，KL 偏差 <1%。

** Harness
agent 在无 GPU、无网络（仅模型 API）的沙箱里，只能经 4 个命令（qda / kl / qsched / handin）访问系统；reference traces 和测试集不可见，且可读文件会预先扫描是否含测试题。KL 评分任务中位 5 s 启动，GPU 占用率 72%。

* 结果（§6）
- 4 个模型：Qwen3.5-9B、Qwen3.6-35B-A3B（MoE）、Qwen3.8-27B、R1-Distill-Llama-8B；基准 AIME25 + HMMT、GPQA-D、LCB v6、IFBench（R1-Llama 用 IFEval），最长 81,920 token。
- 相对最强公开配方平均 +0.9 / +1.4 / +2.2 pt（W4A16 / W4A8 / W3A16），最高 +6.1 pt（R1-Llama W3A16）。Qwen3.8-27B W4A16 甚至比 BF16 高 0.3 pt。
- 并非全胜：Qwen3.6-35B-A3B W3A16 比 GSQ 低 0.2 pt，W4A8 只领先 0.1 pt。
- GLM-5.3-Flash NVFP4 W4A4：恢复 FP8 的 98.3%，NVIDIA / Red Hat 发布版 96.9% / 96.3%；checkpoint 183.6 GiB，更小；一次搜索 6.5 h / 16×GB300 / $69 token。
- 对比 ParoQuant：解码快 1.30–1.75×（无在线旋转）。
- 对照：同一个 agent + ModelOpt 及其 recipe-search skill，在 test benchmark 上选点仍低 0.5–1.3 pt；换成 greedy / ASHA 在 W4A8、W3A16 上低 0.2–1.2 pt；去掉库和调度器（"w/o infra"）低 0.2–0.5 pt、方差更大、代码量 3×（3.1k vs 1.1k 行）、从不尝试 rotation。
- 搜出的规律：没有任何公开技巧处处有效（自生成数据让 Qwen3.6 KL −30% 却让 R1-Llama 变差；AWQ scaling 在 Hadamard 旋转之后几乎无增益）。12 个最终配方里 KL 降幅最大的一步：rotation 5 次、distillation 4 次、自生成数据 2 次、FP8 scale 搜索 1 次。5/12 趋同于"自生成数据 GPTQ + scale distillation"，固定成配方后 W4A16 追平或超过最佳公开，但 Qwen3.5 W4A8/W3A16 分别落后 QDA 2.2 / 5.0 pt。

* 几点读后判断
- "agent 比搜索算法强"的证据只来自一个模型（Qwen3.6-35B-A3B）、三次搜索；W4A16 上 greedy/ASHA 与 QDA 只差 ≤0.1 pt，说明部分收益来自库和 KL，而非 agent。
- 系统有大量人工设计（评估隔离、sandbox、库）——贡献主要在基础设施，agent 部分是黑盒（Claude Code + Opus 5.5，一套 task statement）。
- 成本口径：64 GPU·h 不含最终评测；$19–75 token 是 agent 费用。每个新「模型×精度」都要再来一次。
- 代码、库、evaluator、harness 均为 "will release"，目前不可复现。
