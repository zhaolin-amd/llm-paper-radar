* 问题

先看一个只有两个权重的迷你量化。某个输出通道只有两个输入特征，两个特征在校准数据上几乎一模一样
（比如两个几乎重复的神经元），对应的权重都是 0.4。真实输出就是 0.4 * 特征1 + 0.4 * 特征2，
约等于 0.8 倍的那个特征。现在要把权重压成整数（刻度间隔 1，只能取 0、1 这类整数）。（这个例子是我为讲解构造的，
不是论文里的。）

最朴素的做法是各自四舍五入：0.4 -> 0，0.4 -> 0。结果两个权重都变成 0，输出整个没了，
误差有 0.8 倍特征那么大。可两个权重加起来本该是 0.8，只要有一个被取成 1 就好得多。

GPTQ 就是为这种情况发明的。它先把第一个权重取成 0，发现丢了 0.4，就立刻让第二个权重去补：
0.4 + 0.4 = 0.8，再取整得 1。最终 (0, 1)，输出误差只有 0.2 倍特征。这就是 GPTQ 的"误差补偿"：
量完一个，把误差分摊给还没量的兄弟。它在 4 比特上把一整批大模型的精度保住了，成了事实标准。

然而一直没人说得清它为什么管用。流程是一串代数更新：取整、算误差、乘上 Hessian 逆的某一列、
加到剩余权重上，再来一轮。每一步都是局部贪心，没有人证明过整层的误差不会失控。出了问题（比如
某一层突然崩掉），调参的人只能换顺序、改阻尼系数碰运气，因为这个算法没有可以画出来的"形状"，
也没有可以拿来预判的最坏界。

前人动过它的边：OBQ（Optimal Brain Quantization）给出了补偿公式的来源；QuIP 证明了 GPTQ 的一个等价变体
带有误差保证，但那还是代数形式的。这篇论文的作者盯着上面的两权重例子问了一句别人没追的话：
这个"补偿"到底在几何上做了什么？

* 翻译

答案出奇地干净：*补偿就是投影*。他们证明，把 GPTQ 的循环方向反过来看（从最后一维走到第一维），
它和数学里一个 1986 年的老算法完全一回事——Babai 最近平面算法，用来在格点上找离目标最近的点。

回到两权重例子，看这台"格点"是怎么搭起来的。

** 先搭格点

把每个输入特征在校准数据上的取值看成一根向量，叫它特征向量。权重乘上特征向量再加起来就是输出，
所以所有"整数权重"能凑出的输出，构成一张格点：每根特征向量拉一个方向，格子间距由刻度决定。
真正的输出（满精度权重给出的）是格点之外的一个目标点。量化就是在格点上找离目标最近的点。
这就是一个经典的最近向量问题（CVP）。

在我们的例子里，两根特征向量几乎平行：格点又细又长，像一条几乎压成直线的窄带。
目标点就在那条窄带里（0.8 倍特征）。

#+begin_example
  两根几乎平行的基向量 b1, b2，目标 y = 0.4 b1 + 0.4 b2 (约 0.8 倍 b)

        b2 ->
       /
      /  y (目标)
     /  .
    +------------> b1       (b1 与 b2 夹角很小)

  整数格点： (0,0) (1,0) (0,1) (1,1) ...  落在近乎同一条线上，
  只是沿线位置分别为 0、1、1、2 倍的特征
#+end_example

** 一次一个方向，沿着垂线落地

Babai 的做法是一步一步"落地"。先挑一个基向量，把格点切成一族平行的超平面（二维时是平行线），
这一族的间距由该基向量里"不能被其他基向量代替的那部分"决定——这部分叫它的独有长度。
目标点会落在两张相邻的平面之间，Babai 就选更近的那张，把目标沿垂线投到它上面。
然后在这张平面里，对剩下的基向量重复一遍。

在例子里，第一步先处理权重 1（GPTQ 的顺序）：权重 1 的独有长度极短（它几乎能被权重 2 代替），
所以那一族"平面"贴得极密。目标点离最近的平面只差一点点，取整的代价几乎为零，系数取 0。
这一步丢掉的 0.4 去哪了？投影之后，目标在这张平面里的位置，需要重新用权重 2 来表达——
权重 2 的目标系数从 0.4 变成 0.8。这个"重新表达"就是 GPTQ 的误差补偿。第二步取整 0.8 -> 1，
最终 (0, 1)，和上面的结果一样。

这里有两个事实值得停一下。

第一个：GPTQ 的补偿公式（乘 Hessian 逆那一列）和这个投影后的重新表达，是同一个数。论文用对偶基
把它证了出来，所以补偿不是"启发式的修补"，而是最近平面算法里的一个必然步骤。

第二个：想象一个"逆序"。GPTQ 习惯从第 1 维做到第 c 维，Babai 的标准写法是从第 c 维做到第 1 维。
论文说的 "back-to-front" 只是索引约定：GPTQ 用什么顺序，Babai 就把基向量按相反顺序排好再跑。
任何顺序的 GPTQ 都是 Babai。（Babai 里的 LLL 基约化论文刻意没用——它对每个输出通道的刻度敏感，
批量化不了，也没法配合裁剪。）

** 结局一：最坏误差有了上限

既然是 Babai，就继承 Babai 的保证。每一步取整最多错半格，而不同步骤的误差方向两两垂直，
平方误差可以直接加起来。于是整个输出通道的平方误差不超过：

*每个方向的"独有长度平方 x 刻度平方"加总，再除以四。*

回到例子：特征长度记为 1，两个独有长度是 1 和极小的一个数，上界约为 (1 + 0) / 4，所以误差最多
0.5 倍特征。GPTQ 实际 0.2，在界内；而朴素四舍五入的 0.8 超过了这个界——*四舍五入没有这条保证，
Babai（也就是逆序 GPTQ）有。*

两个细节，不要漏掉。其一，这个界和权重是什么无关，只由 Hessian（独有长度）和刻度决定，
所以可以在量化之前就算出来。其二，它要求"不裁剪"。如果补偿之后的权重（例子里的 0.8）超出了整数范围
（比如格式只允许到 0），只好被截断，误差就超过半格，界作废。算法等价对裁剪仍然成立，保证不成立。

** 结局二：顺序影响多大

界里的"独有长度"取决于量化顺序：Gram-Schmidt 里最先被正交化的那根向量把自己的整个长度都贡献进去，
后面的只贡献新增的部分。所以顺序的作用是决定谁来"交整个长度"。论文用 tr(D)（独有长度平方之和）作代理，
比较了几种顺序在 Qwen3-8B 第 18 个 Transformer 块上的值：

#+begin_example
  顺序           QKV 层     Gate.Up 层   Down 层
  随机(平均)     1.168e8    1.194e8      1.322e9
  act-order      7.400e7    6.052e7      1.222e9
  min-pivot      7.323e7    5.990e7      1.221e9
#+end_example

act-order（GPTQ 老就有的"按激活能量排序"）已经把 QKV 层和 Gate.Up 层的 tr(D) 压低了约 37% 和 49%。
作者新提出的 min-pivot（每步取当前剩余里最短的向量）比 act-order 再低一点点，约 1%（O 层不到 1%）。
作者自己的话是下游精度提升 "modest"（有限）。这条结果被写得很老实：理论给出了方向，
但便宜的老办法已经拿走了大半好处。

** 一个反直觉的副发现：让格点变粗，反而更差

既然界要求不裁剪，最直接的想法是把刻度放大，让所有权重都落在范围内，不就不裁剪了吗？论文的结论
恰恰相反：*放大刻度会放大界*（界对刻度是二次的），误差反而会超过带裁剪的 MSE 方案。

在例子上的意思是：为了容纳一个特别大的权重而把整个通道的刻度翻倍，那两个小权重的取整就变得很粗，
得不偿失。正确的做法是保持格点细，承认有少数权重会溢出，然后给它们另想办法。作者给了两条路：

- SSQR：小刻度整数管大部分权重，溢出的权重单独存成稀疏的浮点数；
- HPTQ：整个矩阵只用一个标量刻度，整数不设上限，再用 Huffman 编码——常见的小整数用短码，
  罕见的大整数用长码，让"大值"贵一点而不是被截掉。

Qwen3-8B 上（WikiText-2 困惑度，原模型 9.73），在平均 2.125 位：HPTQ 13.97，GPTQ 57.51，
把 GPTQ 换成 RTN 的对照 HRTN 593.05。3.125 位：HPTQ 10.34，GPTQ 12.77，HRTN 10.75。
HPTQ 对 HRTN 的差距，才是"误差传播 + 不裁剪"本身的功劳（两者都用了 Huffman）。
Llama-2-7B 上（WinoGrande / PiQA，满精度 69.46 / 78.13），2 位附近：HPTQ 2.125 位拿到
65.82 / 73.56，GPTQ 49.64 / 56.20，QTIP 2.0 位 64.70 / 75.90，AQLM 2.02 位 65.67 / 74.76。
同组实现了 SSQR 的 CUDA kernel，在 Ampere 显卡上对 PyTorch BF16 端到端约 2 倍加速。

但要看清楚：这些实验检验的是"不裁剪 + 误差传播"这个设计方向，没有把界和真实层误差画在一起对照，
所以没有直接验证 Babai 的界。故事讲到这里，读者手里已经有几件东西：格点的词典、投影与独有长度、
不裁剪这条前提，还有顺序这个旋钮。下面一件一件拆开。

* 核心概念

** 词典：基向量就是校准激活

*一句话*：一个输出通道的量化问题 = 一个格点上的最近向量问题；基是校准激活按刻度拉伸，
目标是满精度输出，整数权重是格点坐标。

*回到例子*：两根特征向量是基，刻度决定它们各被拉长多少，目标点是 0.8 倍特征，整数权重 (0,1) 是格点上的坐标。
少了这本词典，GPTQ 的取整误差只是权重空间里的数字；有了它，才能说"权重离整数差多少"等于
"输出空间里离格点多远"。

*为什么重要*：论文的 Theorem 1 还补了一条：Hessian 的任何分解因子给出的格点彼此只差一个旋转，
所以只需要 H，不需要整个校准矩阵，Cholesky 因子就够用。后面所有证明、所有算法都建立在这一步上。

** 独有长度与投影：误差界的原料

*一句话*：基向量排好顺序后，每根扣掉前面所有向量能表达的部分，剩下的"独有长度"就是该方向上取整
的刻度；这等价于 Hessian 做 LDL 分解后的对角元 D。

*回到例子*：权重 1 的独有长度极小，说明"另一个特征几乎能代替它"，所以取成 0 不心疼；
权重 2 的独有长度约等于整根向量，所以它的取整才是误差主要来源。Babai 的每一步就是"沿一个方向取整，
再沿垂线投影到平面上"，误差分量两两垂直，才能直接平方相加。把我们的两权重例子里的最后一步换成
一个必须动用补偿的情形，补偿的比例就是 Hessian 逆里的那个比值（Theorem 2）。

*为什么重要*：它是界的原料。没有"独有长度"，就写不出"每个方向最多错半格"的界，也解释不了
为什么相关性强的特征可以互相补偿（独有长度小）。

** 不裁剪：让保证成立的那个前提

*一句话*：Babai 的界依赖每步取整只差不超过半格；一旦补偿后的值超出整数范围被截断，这条就断了。

*回到例子*：把 0.8 这个补偿后的权重强行截断到 0，误差立刻回到 0.8 倍特征，超过界。论文因此重新设计量化方案，
让"溢出的权重"有地方去：SSQR 存成稀疏浮点，HPTQ 用 Huffman 编码的无界整数。

*为什么重要*：这是本文最重要的*设计选择*，不是一个组件。它把"理论的保证"和"能部署的格式"的接缝
暴露出来：现实里的 INT4 一定要裁剪，保证就不适用。后面博导审稿里的疑问大多长在这条缝上。

** 顺序：唯一能自由调的旋钮

*一句话*：量化顺序只通过 D 进入界；找最优顺序是 NP-hard，只能用启发式（act-order、min-pivot）。

*回到例子*：两根特征向量一长一短时，让谁先"交整个长度"是有差别的：让较短的先交，总和更小。
这也是 min-pivot 的几何含义："总是先取当前最短的剩余向量"。

*为什么重要*：它说明了为什么老办法 act-order 一直有效，也说明了为什么新办法只能带来小幅改善：
便宜的启发式已经站在了好位置上。

* 洞见

GPTQ 的补偿不是调出来的技巧，是格点上的一次投影；一旦看见了这个形状，"能不能保证"变成可以
计算的问题。把一个靠经验好用的算法认出是一个有几十年历史的算法，价值就在于：你从此知道它在
什么条件下一定行（不裁剪），在什么条件下没有保证（裁剪），也知道旋钮只有一个（顺序）。

* 博导审稿

*选题眼光*：问题是真的。GPTQ 是最常用的 PTQ 算法之一，"为什么它管用、何时不管用"确实没人说清楚，
不是人造缺口。同期还有 Birnick 的证明（论文脚注承认），说明这条路是被各方看到的，而本文的几何解释
（投影图、独有长度）更适合拿来教人和做设计。

*方法成熟度*：等价这一半是干净的数学，也给了代数证明（App.C 三步）。让我不放心的是从定理走向算法
改进的那一步，有几个没被充分讨论的预设：

1. 界是逐层、逐输出通道、基于校准集 Hessian 的。层与层之间怎么累积（后面层的输入受前面层量化影响）
   完全不在界里；D.3 里的 Hessian 是用满精度模型跑出来的。端到端怎样，界不管。
2. "界紧"是对最坏目标点而言，LLM 的权重不是最坏点。论文补的 1/3 期望值依赖"权重在正交长方体内
   均匀分布"，且要求刻度足够小。界到底比真实误差松多少，文中没有给图。如果松很多，用它来指导设计
   的说服力就要打折。
3. 选顺序时假设各刻度近似相等（min-pivot 优化 tr(D)），但 MXFP4 / NVFP4 这类小组格式里刻度的差异
   恰恰不能忽略。
4. 结语说 MXFP4 / NVFP4 近似不裁剪，所以分析"直接适用"。但 FP4 的网格不是等间距的，而 CVP 的
   格点是等间距整数格，这一步没有展开，我不确定它是否真的直接适用。

如果这篇论文错，最可能错在这里：*界是不是对真实 GPTQ 误差的有用刻画*，而不是等价本身。

*实验诚意*：诚实的部分很多。min-pivot 只带来"modest"改善，作者直接写了；HRTN 这个对照是认真的，
能隔离出"误差传播"的净贡献。需要追问的部分：(a) HPTQ 的位宽是 Huffman 平均码长，和 GPTQ 的定长位宽
按平均位宽比较，格式不对等；".125" 的算法在 HPTQ 上没有解释，我不确定它是不是为了对齐 GPTQ 的
group-128 刻度开销；(b) 与 AQLM / QuIP# / QTIP 的对比数字取自各自论文，只用 WinoGrande 和 PiQA，
设置未必一致，而 Qwen3-8B 的 MMLU 在 2.125 位仍从 73.02 掉到 52.99；(c) SSQR 在 2.445 位
的 Llama-2-7B 上只有 50.04 / 56.15，不及 HPTQ；(d) 加速只对比 BF16，没有对比现成低比特 kernel，
kernel 也只给了 SSQR，没有给 HPTQ（变长解码的开销没有出现）；(e) Table 5 里 GPTQ 的 SciQ 数值
与 PiQA 列完全重复（3.125 位和 2.125 位），像表格笔误；kernel 正文写 RTX 6000，图注写 A6000。

*写作功力*：理论部分的 Table 1 词典和 Figure 1 的取整边界对照写得好，是整篇最值钱的部分。
第 5 节明显更像另一篇工程论文，和前面的定理接得不紧。

*判决*：weak accept。等价与几何解释是扎实且有教学价值的贡献；定理到应用之间缺一张"界对真实误差"的图，
应用部分的证据只支撑"不裁剪 + 误差传播更好"，不支撑"界在指导设计"。

* 启发

- *迁移*：Babai 的界与权重无关，只取决于 Hessian 的独有长度 D 和刻度 s，所以你可以在量化之前、
  对每一层用校准数据算出 (T^-1 s)^T D (T^-1 s) / 4，把它当作"这层有多难量化"的廉价指标，
  用来决定哪几层给更多位宽或更小的组。（我的建议，论文没做；先拿一个 8B 模型把这个指标与实际逐层
  输出误差画散点图，若相关性高再用。）
- *混搭*：这个仓库关注的 MXFP4 / NVFP4 路线（组 32 / 16、AbsMax 刻度，近似不裁剪）正是论文点名的
  适用场景。可以把 min-pivot 的 tr(D) 当作"换顺序值不值得"的诊断：若 act-order 与 min-pivot 的 tr(D)
  差距像 Table 2 那样不到 2%，就不用换。前提是先确认 FP4 非等间距网格对界的影响。
- *反转*：默认的做法是 GPTQ 出问题就调阻尼和顺序碰运气。可以反过来先问一句：这层有多少权重在补偿后被
  裁剪了？裁剪比例高的层界失效，优先对它们做异常值处理或放宽范围，而不是继续试顺序。顺手写一个 20 行的
  对拍：随机 H、随机 w，比较 GPTQ 与 Babai 的输出是否逐位相同，再打开裁剪看分歧在哪一步出现——这能让你
  亲手确认等价与它的边界。
