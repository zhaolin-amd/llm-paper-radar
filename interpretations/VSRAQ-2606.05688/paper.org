* 问题

先看一个只有四个专家的迷你路由。（这个例子是我为讲解构造并验算过的，不是论文里的。）
一个 MoE 层里有 A、B、C、D 四位专家，每个 token 来了，路由器给四位打分，只挑分数最高的两位干活。
某个 token 在全精度模型里的分数是：A 2.0，B 1.2，C 1.1，D -0.5。入选的是 A 和 B。C 只差 B 一线，0.1。

现在把模型量化成 4 位。每个数都被粗暴地塞进更粗的格子，分数跟着抖了一下：
A 还是 2.0，B 掉到 1.12，C 涨到 1.18，D 没动。每个分数最多偏了 0.08，用任何"误差够不够小"的标准看，这都是一次很成功的量化。
可是现在 C 比 B 高了，入选的变成 A 和 C。这个 token 被送进了另一位专家，后面整条计算路径跟着变。

这就是 MoE 量化独有的麻烦。普通模型里，量化是"每个数算糙一点"，结果跟着糙一点，偏移是平滑的。
MoE 里还多了一个岔路口：选谁是靠"分数排名 + 硬截断"来定的。分数连续地动，选择却是跳着变的。
数字差得再小，只要跨过那条线，这个 token 走的就是另一条路。生成长答案时，一步走偏，下一步的输入已经变了，偏差一路滚下去。

前人怎么试的？最早的路是照搬普通模型的量化方法：让量化前后每一块的输出数字尽量接近
（GPTQ、AutoRound 这一脉，目标是"块输出的均方误差"，雷达里把这类归为 reconstruction-only PTQ）。
这条路盯的是数值，岔路口不在它的视线里：上面那个例子里，块输出可以相当接近，选的专家却已经换了。
再后来有人（EAC-MoE、EAQuant，雷达里归为 router-aware quantization）意识到要保护路由，让量化前后路由器给出的分数逼近。
比如只在原本入选的专家上做分数的均方误差。这一步是对的，但你在例子上算一下：
原入选的 A、B 两个分数的误差，平均只有 (0 + 0.08^2) / 2 = 0.0032，小得几乎看不见。损失函数觉得一切正常，而 B 和 C 已经换了位。
分数贴近，不等于座次不变。

VSRAQ 的作者就从这里下手：既然你在乎的是"谁入选"，为什么不直接让损失看见"入选者和落选者之间的那条线"？

* 翻译

*锚点：还是那四位专家。方法像在 B 和 C 之间立一块界碑，量化的时候盯着界碑别被推过去。*

*转折（一句话）：* 分数有两层信息，一层是"值"（每个专家多少分），一层是"结构"（谁排在谁前面，第 k 名和第 k+1 名隔着多远）。
前人只保了值；作者把结构也写进损失。

*一步步看它怎么在那个例子上动手。* VSRAQ 不是一个新的量化算法。它是在已有的量化框架里加一项损失，
他们选的框架是 AutoRound：原来的目标是让每个解码块的输出贴近全精度，VSRAQ 在这个目标后面加一个"路由对齐"项，系数不大（0.01 或 0.1）。
路由对齐项由两半组成。

第一半，值对齐，是保底的。先沿用前人的做法：把全精度选中的那几位专家（A、B）的分数，在量化后拉回原样。
再加一层作者自己的修正：现在很多新模型（DeepSeek-V3、Nemotron-3-Nano、GLM-4.5）用的是 sigmoid 路由，
即每位专家的分数各自过一道 S 形曲线，变成 0 到 1 之间的亲和度。S 形曲线中间陡、两头平，
所以分数落在 0.5 附近的专家，同样大小的抖动会被放大成更大的分数变化；贴近 0 或 1 的，抖了也看不出来。
于是作者在分数上再做一个均方误差，并给每个专家乘一个"敏感度权重"，中间陡的地方权重大，两头平的地方权重小。
意思是：校准的力气有限，别花在不影响选择的地方。

第二半，结构对齐，是论文新东西，又拆成两件。
一件管入选者内部的座次：A 要比 B 大，量化后 A 还是要比 B 大，倒过来就罚。
另一件管界碑：全精度里 B 比 C 大 0.1，量化后就要求 B 和 C 的差也尽量是 0.1。
回到例子：量化后 B 减 C 是 -0.06，和 0.1 差 0.16，平方是 0.0256，是前面那个值对齐损失 0.0032 的八倍。
这一项就是那个能看见翻转的眼睛。（排序那一件在这个例子里不吭声，因为 A 和 B 的座次没变；
抓住"落选者爬进来"的是界碑这一件。注意它是让余量"保持原样"，不是"越大越好"，量化后余量变大也会被罚。）

*设计里的几个小选择。* 作者只看第 k 名后面紧邻的那一位落选者（b=1）；
参考的"谁是第几名"一律以全精度的排序为准；整个目标只在校准时存在，量化完了就卸掉，所以推理图没变，没有任何额外开销。
论文还强调这是个"插件"：不绑定 AutoRound，原则上可以接到别的重构式量化上。

*结局：三组数字。*
- Solar-Open-100B，NVFP4（权重和激活都量化）：生成类任务平均分，AutoRound 61.78，只加前人那项 63.86，VSRAQ 64.43，未量化是 73.62。
  与未量化的差距从 11.84 分缩到 9.19 分，约收回两成。
- Nemotron-3-Nano-30B-A3B，NVFP4：生成类 69.10 / 69.47 / 70.92，未量化 73.64，差距从 4.54 分缩到 2.72 分，约收回四成。
- Solar-Open-100B，W4A16（只量化权重）：生成类 72.19 / 71.66 / 73.22，未量化 73.62，差距从 1.43 分缩到 0.40 分，约收回七成。
  困惑度（WikiText-2）也都往下走，如 Solar W4A16 从 7.12 降到 6.81，NVFP4 从 7.22 降到 6.90。
  路由一致性直接测：在 61 万多个 token 上算量化前后入选专家集合的重合度（Jaccard），VSRAQ 最高比基线相对提升 11.29%。

*这篇里最反直觉的一件事：好处几乎只在"长生成"里出现。*
同一批量化模型，换成选择题（给每个选项算似然，一步打分），几种方法都紧贴未量化，差距只有零点几到一分，改进也就十分之几。
一旦让模型自己写一长串推理再抽答案，差距立刻拉开。作者的解释是：路由的偏差每一步都会通过隐藏状态传给下一步，滚雪球。
这也提醒你一件事：评估量化 MoE，只看困惑度或选择题，会低估路由翻转的代价。

*另一个同样诚实的发现：结构项并没有处处加分。*
消融表里，Solar W4A16 的困惑度在"加 sigmoid 项"时最低（6.72），再加结构项反而回到 6.81；
逐层 Jaccard 图里，VSRAQ 和前人的单项曲线在大多数层贴得很近，只有 AutoRound 在少数层（尤其浅层）明显更低。
也就是说，"11.29%"主要是相对原始 AutoRound 的最大差距，不是处处如此。

* 核心概念

*一，值对齐里的 sigmoid 敏感度权重（给"校准力气"分配的设计）。*
一句话：对每个入选专家，分数的误差乘一个 p(1-p) 的权重，p 是它的 sigmoid 分数，权重在 p=0.5 处最大。
回到例子：A 的分数 2.0 过 sigmoid 约 0.88，B 的 1.2 约 0.77，都在偏陡的一侧；若某专家分数落在 0.5 附近，
同样 0.08 的 logit 偏移会换成更大的分数偏移，权重也更大。没有它，所有入选者被一视同仁，
校准容量被饱和区那些"怎么抖都不影响选择"的专家分走。论文还说这项系数 alpha 取得小（0.3），
只是 top-k 直接匹配的辅助修正。

*二，边界余量（让损失看得见"落选者"）。*
一句话：取全精度里第 k 名与紧随其后落选者的分数差，要求量化后这个差也一样。
回到例子：B 与 C 的差，全精度 +0.10，量化后 -0.06，损失 0.0256。它的特别之处在于，
前人所有的值对齐项都只看"原本入选的专家"，落选的 C 根本不在损失里，所以 C 怎么爬上来它看不见。
少了它，这篇论文就没有任何东西能区分"B 小幅下滑"和"B 被 C 顶掉"。
另有一个和它配对的排序项，只管入选者内部的座次，抓不到例子里的翻转，但保证混合权重的顺序不乱。

*三，只改校准目标、不改推理图（设计选择，也是它能被采用的原因）。*
一句话：所有新增损失只在量化参数优化阶段出现，量化完成后的模型结构、精度格式、算子都和 AutoRound 产物一模一样。
回到例子：量化后的模型里没有任何"界碑检查"，只是量化参数（缩放、舍入）被校准得让 B 不要被推过 C。
代价是：它只能通过调整量化参数来间接保住路由，无法在推理时纠错；好处是对部署方零改动，显存与延迟和同精度 AutoRound 完全相同。
（权衡点：路由损失强度 lambda_router 要按模型调——Solar 用 0.01，Nemotron 用 0.1，论文只说是让路由损失与重构损失量级相当。）

* 洞见

守住一个硬门槛，不要靠把门槛两边的数字压得更近，要把"有没有过线"本身当作要优化的东西。
一个门槛两侧只差一线的时候，数字误差小和结果不变是两回事；你该盯的是那条线，不是线两边的数。

* 博导审稿

选题眼光：困境是真的。MoE 量化里路由翻转是实打实的部署痛点，不是人造缺口；而且论文把评估拉到长生成，这一点选得对，
因为这是路由偏差真正显形的地方。

方法成熟度：巧劲，不是蛮力，机制也容易接进现有流程。但我想追问几个没被讨论的预设。
一，路由只在"单层"上对齐，并且以该层全精度的排序为锚，而这个锚是在全精度模型里、全精度输入下算出来的。
量化模型里上一层如果已经走偏，这一层的输入分布已经变了，再拿全精度那一层的排序当"正确答案"，是否还成立，论文没有讨论。
这是方法最可能出错的地方：它保的是逐层一致，不是整条路径一致。
二，"保住原选择就是好"这个假设没有被独立验证：本文没有"强制沿用全精度路由"的对照，
无法把"路由一致带来的收益"和"重构更好带来的收益"分开；前人 EAC-MoE 做过这样的隔离实验，本文没有。
三，只守第 k+1 名（b=1），第 k+2、k+3 名也很近时守不住，没有 b 的消融。

实验诚意：偏弱。基线只有 AutoRound 和 TopK-MSE 两条，论文自己点名批评的 EAQuant 没有对比，
所谓"router-aware baselines"其实只有一条；所有数字是单次运行，没有方差，Nemotron 似然选择题上 70.18 对 69.96 的差距在噪声里；
消融只给了困惑度，没有生成类任务的逐项消融，所以结构项在下游任务上到底贡献多少无法判断，
而且在 Solar W4A16 上加结构项后困惑度反而变差（6.72 到 6.81）。只测了两个模型，且只在 4 位上测；
作者自己说预期在 2、3 位上收益更大，那恰恰是最需要证明的地方。没有放出代码（雷达记录里 code_url 为空）。

写作功力：清楚，机制说得明白，局限也自己写了（4 位下噪声小，收益偏温和）。美中不足是 11.29% 这个数字没说明是哪一层、什么设置，
容易被读成平均提升。

判决：weak accept 到 borderline。想法本身站得住，也是这条线上第一个把"排序与边界"显式写进量化损失的工作；
但证据只够证明"有一点用"，还不够证明"结构这一半是必要的"。

* 启发

这意味着你可以做几件手上能动的事。

迁移：你在量化任何带"门控或路由"的模型时（MoE 之外，还有稀疏注意力的 top-k、检索里的 top-k 重排），
别只看输出均方误差；加一个"原选中的 k 个与第 k+1 个之间的余量保持"的小损失。实现很小：取 logit 排序、取 k 与 k+1 两个位置做差、做一次均方。

反转：评估量化 MoE 时，把默认的"困惑度 + 选择题"停掉，至少加一组长生成答案抽取的任务，并统计逐层 Jaccard 一致度。
选择题几乎不受路由影响，会让你误以为量化无损。

混搭：这个目标只在校准期加损失，所以可以直接叠在你现有的 AutoRound、GPTQ 之类流水线上，也可以和 MoEQuant 那样的"专家均衡校准集"、
QuantMoE-Bench 那样的"分组件位宽"同时用，彼此不冲突（论文没有测试叠加，需自己验证）。

先做的小实验：在你自己的 MoE 上，把全精度路由强制塞进量化模型，看长生成任务能回多少分，
这一步决定路由一致性对你的模型到底值多少钱，再决定要不要接 VSRAQ。

* 前人脉络（供回溯，不属于七拍正文）

雷达里 related_methods 给出的两类旧路：reconstruction-only PTQ（仅最小化重建误差，路由一致性差）、
router-aware quantization（仅对齐 logits，未保留 top-k 结构）。
paper-river/VSRAQ-2606.05688.org 把它们放进更长的谱系：OBS/OBD（用二阶信息判断参数重要性）-> AdaRound / GPTQ -> AutoRound（VSRAQ 的基座）；
MoE 一侧是 Shazeer 2017 的 top-k 路由 -> Switch Transformer 的 top-1 -> QuantMoE-Bench / MoEQuant（MoE 要特殊对待，但没碰"选择"本身）-> EAC-MoE / EAQuant（保路由值）-> VSRAQ（再保路由结构）。
其中 EAC-MoE 的"强制沿用全精度选择，困惑度 4.65 回到 4.21"出自该 river 文件对 EAC-MoE 的转述，本文未独立核实。
river 文件里把排序项说成"按住 top-k 相对顺序"、把余量项说成"撑开差距"，与本文式 13-15 不完全吻合：
排序项只管入选者内部，余量项是"保持"而不是"最大化"，以本文公式为准。
