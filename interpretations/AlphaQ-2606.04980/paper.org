* 问题

你手里有一个混合专家模型（MoE），要塞进一张显存小得多的卡。办法只有一个：把权重压到几个比特。
可预算是死的——平均每个线性层只能摊到 3 个比特。三个层，总共 9 个比特的名额，怎么分？
（这个小例子是我为讲解构造的，不是论文里的；后面全篇都在这三个层上讲。）

平均分最省事：每层 3 比特。可层和层不一样。有的层训得扎实，里面存着真东西，压狠一点输出就走样；
有的层训得潦草，几乎是随机的，压到 2 比特也没人发现。所以更聪明的分法是：重要的层拿 4，不重要的拿 2。
卡点只有一个：怎么知道谁重要？

前人的答案几乎一致：拿一小撮校准数据喂进模型，看哪个专家被叫得多、压它会让输出偏多少，据此分。
MC-MoE 里的 PMQ 就是这么做的，MoEQuant 修的是"校准样本在专家之间不均衡"，MxMoE 把粒度细到线性块并配了专用 kernel。
这条路能走，但有堵墙：前沿 MoE 的真实训练数据是公司机密，你手里的校准集永远是个替身。
论文给了一个干净的证据（图 1）：同一个 Mixtral-8x7B，用 C4、MATH、GitHub 代码三种数据做校准，
分出来的比特配置明显不同，模型就跟着偏科——拿 MATH 校准，数学题强、写代码弱；拿代码校准，反过来。
换句话说，校准集是什么口味，压出来的模型就是什么口味。这堵墙不是把校准集做大做匀就能拆掉的：
作者在 OLMoE 上试了多域混合校准，结论是失败模式换了位置，没有消失。

于是问题换了问法：既然数据靠不住，一个层的"重要性"能不能不经过数据，直接从它自己身上读出来？
还真有人几年前就干过这件事，只是没人拿它来分比特。

* 翻译

作者看到的入口是 Martin 和 Mahoney 的"重尾自正则"（HT-SR）理论。它的说法很朴素：
把一个权重矩阵 W 拿出来，算 W 的转置乘 W，再看这个矩阵的特征值怎么分布。
训练前，权重近似随机，特征值挤成一个规整的"团"；训得越透，团的一侧就拖出越长的一条尾巴——特征值少数几个特别大。
尾巴越长，说明矩阵里学进了越强的结构。他们用一个幂律指数 alpha 来量这条尾巴，alpha 越小，尾巴越重，层训得越好。
整个过程不碰训练数据，也不碰测试数据。

转折就在这儿：*既然 alpha 能不靠数据说出一个层训得好不好，它就能不靠校准，告诉你该多给谁几个比特。*
把这个看法放回那三个层上，方法一步步展开。

*第一步，给每个层量一个 alpha。* 对三个层各算一遍特征值谱，取最大的那一堆作"尾巴"，用 Hill 估计器拟合幂律指数。
两个工程细节让这个数能跨层比：一是尾巴从哪儿算起，不让人手选，而是对齐到谱的峰值；
二是矩阵形状不同会让谱形状失真，所以把每个矩阵切成固定的 256 乘 256 小块再平均。
在我们的三层里，假设量出来 alpha 是 3、4、6（构造值）：第一层尾巴最重，最该保护；第三层最轻，最该牺牲。
真实模型里这个差异很大：论文的图 3、图 4 显示，不同 block 之间、同一层里不同专家之间、
甚至同一个专家的 up、gate、down 三个投影之间，alpha 都不一样。这一点直接导出两个结构选择：
预算不该每个 block 各分一份，而该全模型统一分（全局预算）；粒度不该停在整个专家，而该下到线性层（层级粒度）。

*第二步，把 alpha 变成"这个层被压坏有多疼"。* 光有 alpha 还不够，压 1 个比特和压 2 个比特的伤害不一样，
大层和小层占的位数也不一样。作者的做法是先写出"量化噪声有多大"——比特每少一位，噪声大约放大四倍，
再乘上这个层权重本身的方差；然后用 alpha 去放大它：alpha 比全模型中位数小的层，噪声被乘上一个大于 1 的权重，
疼得更厉害；alpha 大的层，权重小于 1。放大的力度由一个指数 gamma 控制，默认值直接从模型里 alpha 的最小值、最大值和方差算出来，不看数据。
在三层的例子里，取 gamma 为 3（构造值，随便挑的一个让数字好看的值，论文默认值要由 alpha 的统计量算）、三层权重方差相同：
alpha 为 3 的层权重约 2.37，alpha 为 4 的层是 1，alpha 为 6 的层约 0.30。

*第三步，解一个背包。* 现在每个层有了一张"选 2、3、4 比特各要付多少疼"的价目表，
目标是总疼痛最小，约束是总位数不超过预算。这是一个标准的多选背包，现成的整数规划求解器几秒钟给出全局最优。
三层的例子上，全部 3 比特的总疼痛约为 0.0573；最优解是 (4, 3, 2)——第一层 4 比特，第三层 2 比特——总疼痛约 0.0434，低了四分之一。
这是我算过的小例子，真实模型里是几百到几千个层同时分，但逻辑一样：把位数从"不疼"的层搬到"疼"的层。

*承重类比：把预算想成一笔装修款，每个房间有一张"漏水风险表"。* 前人是请监理（校准数据）逐个房间浇水看哪里漏，
监理带来的水管不同，查出的漏点也不同；AlphaQ 是看每个房间墙体自己的裂纹纹理（权重谱），不用浇水。
裂纹越深，说明这面墙承重越多（训得越透），预算先补它；alpha 的权重是"裂纹风险"，
噪声项是"这一笔钱补多少能压多少风险"，背包求解器是那个负责分钱的预算员。

*结局：三组数字。* 实验用的是只量化权重、GPTQ 后端、非专家层固定 4 比特、专家层平均 2.5 或 3.5 比特的设置，对手是均匀分配和 PMQ。
- Qwen1.5-MoE，3.5 比特：BF16 平均精度（五项零样本）67.93，PMQ 67.75，AlphaQ 68.04；权重只剩 7.6 GB，约原来的四分之一。
- Qwen1.5-MoE，2.5 比特：均匀 51.99，PMQ 62.18，AlphaQ 65.17。越往下压，差距越大。
- Mixtral-8x7B，2.5 比特：PMQ 70.38，AlphaQ 70.76——只有 0.4 分，基本打平；这个模型专家少、alpha 的方差也小，AlphaQ 没有太多可以分的空间。
另外，在 A40 上 Mixtral 的 2 比特配置把参数从 96.8 GB 压到 13.4 GB；算一遍全部 alpha 只要三到九分钟，是一次性的离线开销。

*副发现：光看噪声大小来分比特，比不分还差。* 论文在 OLMoE-1B-7B 的 3 比特预算下做了一个消融（BF16 为 PPL 7.95、平均精度 70.45）：
均匀 3 比特是 11.78 / 64.73；只用噪声项分配是 11.22 / 63.74——困惑度略好，平均精度反而低于均匀；
只用 alpha 分配是 10.03 / 66.23；把 alpha 和噪声项相乘的最终形式是 9.19 / 67.11。
也就是说，"把误差最小化"这个看起来最自然的目标，单独用并不比不分好；
信号要来自"这个层有多重要"，而不是"压它会偏多少"。两者合起来才最好，且组合方式也有讲究：直接相乘（9.56）不如作者设计的缩放形式（9.19）。
另一条反直觉的发现是第二块拼图：全局预算对逐块预算、层级粒度对专家粒度，在所有设置下都赢，说明 AlphaQ 的收益里有一部分来自这两个结构选择本身。

三件东西在转了：一个来自权重谱的重要性信号，一个把它变成"疼痛价目表"的缩放噪声，一个负责分钱的预算求解。把它们各自拎出来看。

* 核心概念

*一，PL_Alpha_Hill：一个零数据的"这层训得多透"的读数。*
是什么：对一个权重矩阵的特征值谱，取它的尾部，用 Hill 估计器拟合幂律指数，越小越重尾。
回到三层的例子：这就是 3、4、6 那三个读数，不需要喂任何样本就能得到。
为什么重要：它是整个方法"免校准"的来源。没有它，重要性只能从激活频率这类数据统计里来，故事退回到老路。
需要留意的是它是一个有偏的替代指标（相对于原始的幂律拟合），作者的理由是在关心的区域里与原指标相关、且更稳。

*二，用 alpha 去缩放量化噪声（设计选择）。*
是什么：层的损失 = 层权重方差 x 每少一比特放大四倍的噪声 x (alpha 的中位数 / 这层 alpha) 的 gamma 次方。
回到三层的例子：alpha 为 3 的层被放大 2.37 倍，alpha 为 6 的层被缩到 0.30 倍，求解器因此愿意把位数从第三层搬到第一层。
为什么重要：这是 alpha 能进入"预算计算"的接口。消融里只用噪声、只用 alpha、直接相乘、缩放后相乘四种做法的结果都不一样，
说明这个接口本身是一个有效的设计选择，不是装饰。gamma 的默认值也是数据无关的——但图 11 显示不同模型对它的敏感度不同，
DeepSeekV2-Lite 和 Qwen1.5-MoE 比 Mixtral 更敏感。

*三，全局预算 + 线性层粒度（另一个设计选择）。*
是什么：不给每个 block 分固定的平均比特，而是整个模型一份总预算；不以整个专家为单位，而以 up / gate / down 每一层为单位。
回到三层的例子：如果三层来自三个不同的 block，每个 block 被强制平均 3 比特，(4, 3, 2) 就根本不是可选项。
为什么重要：alpha 是"全局可比"的，才有可能跨 block 比较谁更重要；而论文自己的消融（表 5）表明这两个选择在所有设置下都带来增益。
这也意味着读结果时要分清：赢过 PMQ 的部分里，有多少来自 alpha，有多少来自这两个结构选择，论文没有拆开。

* 洞见

一个层的重要性可以不通过"问它被用得多不多"得出，而是通过"读它自己训成了什么样"得出；
当替身（校准集）永远是错的，就别再改进替身，去问当事人。

* 博导审稿

选题眼光：困境是真的。前沿模型训练数据拿不到、校准集偏向它的域，图 1 的偏科是实打实的证据；
选"分配阶段去数据依赖"这个窄口径，比宣称"整条流水线免数据"更诚实。

方法成熟度：整个方法站在一条没有被独立验证的链上——"重尾 = 训得好 = 量化时更不能动"。
HT-SR 说的是前半截（重尾对应训得好、泛化好），"训得好 -> 量化敏感"是论文用结果来支撑的经验命题，
不是推出来的；而一个训得很好却几乎不被路由的专家，alpha 会让你多给位数，真实价值却低，论文没有讨论这类反例；
这恰是被丢掉的激活频率信号本来能补的地方。实际使用的 PL_Alpha_Hill 又是原始 alpha 的有偏替代。
另一个预设：噪声模型假设均匀量化噪声的方差随步长平方变化，对 1-2 比特的极低位宽未必成立。
后端 GPTQ 的误差补偿仍吃校准数据，作者在限制里自己承认。

实验诚意：baseline 只有均匀和 PMQ（另有局部的 BSP / Hessian / AFG / DynaMo 对比，DynaMo 用的是原文数字、未重跑），没有和同样全局分配的 GEMQ 比；
赢面里全局预算和层级粒度的贡献没有被拆开，也缺一个"把 PMQ 的信号放进同一个全局层级 ILP"的对照。
3.5 比特下的增益很小（Qwen1.5-MoE 的 PMQ 67.75 对 AlphaQ 68.04），主要的赢面在 2.5 比特。
多域校准实验和消融只在 OLMoE-1B-7B 一个模型、一个预算上做；最大模型是 Qwen3-30B-A3B，没有更大规模的 MoE。
只量化权重；没有激活量化与端到端系统实验的全面对比。
还有一处细节：摘要说"3.5 比特"，这是专家层的平均，非专家层固定 4 比特，group-wise 的 scale 另有开销，"4 倍压缩"要在这个口径下读。

写作功力：问题和动机讲得清楚，图 1 非常有说服力；弱项是 gamma 的推导放在附录、敏感度又随模型变化，
"数据无关"在 gamma 上不是完全无条件的。

判决：weak accept。思路干净，把一把现成的数据无关的尺子对上了一个真实的痛点，代码已开源；
但"alpha 这个信号本身"的贡献没有被单独拆出来，增益里混着结构选择。

* 启发

迁移：你已有一个 MoE 的混合精度流水线时，可以先把"分比特"这一步换成"读 alpha + 解背包"，后端的 GPTQ 不动，
用 Qwen1.5-MoE 或 OLMoE 这种小模型跑一遍，把结果与你现有的校准法做 A/B。成本是每个模型三到九分钟的一次性离线计算。

混搭：把 alpha 与路由频率一起放进同一个 ILP——alpha 负责"这个层本来有多值钱"，频率负责"实际用得多不多"，
频率信号可以先用 router 权重估计而不是校准集。这样能保住免校准的好处，同时补上论文自己没覆盖的盲区。

反转：别默认"把校准做得更好"是出路。下次遇到"估计误差来自替身数据"的问题，先问能否改成读模型自己，
再回头看校准能贡献什么，而不是反过来。

另有一个落地检查项：在你的实际流水线里，先做一个自己的消融——同样的全局预算、同样的层级粒度，只替换重要性信号（alpha 还是激活频率），
这样才能知道增益里 alpha 真正占了多少。
